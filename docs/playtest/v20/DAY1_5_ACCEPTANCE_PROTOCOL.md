# DAY 1~5 간단 플레이테스트 절차

최종 갱신: 2026-07-26

이 절차는 친구에게 테스트 버전을 빠르게 공유해 화면과 진행의 막힘을 찾기 위한 것이다. 공개 출시의 최종 품질 보증 절차가 아니다.

## 1. 준비

- 테스트할 source SHA 또는 커밋을 기록한다.
- 친구가 실행할 Web 또는 Windows 빌드 하나를 정한다.
- 새 저장으로 시작할 수 있는지만 확인한다.
- 알려진 치명적 문제 한 줄과 피드백 전달 방법을 함께 보낸다.

## 2. 권장 범위

- 인원: 3~5명
- 시간: 1명당 10~20분
- 목표: DAY 1을 직접 시작하고, 가능하면 결과와 재배치를 경험

인원과 시간은 권장치다. 모두 채워야 커밋하거나 다음 작업으로 갈 수 있는 조건이 아니다.

## 3. 친구에게 줄 안내

게임 방법을 길게 설명하지 않는다. 아래 정도만 전달한다.

> 마왕성의 시설과 몬스터를 배치해 침입을 막는 테스트 버전입니다. 편하게 해보고, 어디서 막히거나 보기 힘든지 알려주세요.

## 4. 반드시 물을 세 가지

1. 어디서 무엇을 해야 할지 막혔나요?
2. 필요 없거나 읽기 어려운 글·정보는 무엇이었나요?
3. 배치를 바꿔 다시 해보고 싶었나요?

필요하면 오류가 난 화면의 캡처 한 장만 추가로 받는다. 전체 영상, 복잡한 설문, 개인정보, 로그 묶음은 기본 요구가 아니다.

## 5. 결과 정리

아래 표 하나로 충분하다.

| 참가자 | 막힌 곳 | 불필요·난해한 정보 | 재배치 의향 | 치명적 오류 |
|---|---|---|---|---|
| F1 |  |  | 예/아니요 |  |

- 같은 막힘이 두 번 이상 나오면 우선 수정 후보로 올린다.
- 한 번만 나온 의견은 참고 항목으로 남긴다.
- 시작 불가, 진행 불가, 저장 손상은 즉시 수정한다.
- 취향 차이와 단일 의견을 자동 실패로 처리하지 않는다.

## 6. 기본으로 하지 않는 것

- 70회 자동·물리 전투
- 숙련 QA 24전
- 초회 사용자 10명 고정 모집
- 모든 해상도·브라우저·플랫폼 반복
- 이중 평가자 판정과 복잡한 점수 코딩
- 변경과 무관한 전체 회귀 재실행

위 항목이 필요한 공개 출시 후보 검수는 사용자가 범위와 시간을 승인한 별도 작업으로 만든다.

## 7. 완료 기록

핸드오프에는 다음만 적는다.

- 사용한 빌드 또는 커밋
- 참여 인원과 대략적인 시간
- 반복된 막힘
- 바로 수정할 문제와 보류할 의견

친구 테스트를 아직 하지 않았다면 `사용자 공유 대기`라고 기록하면 된다.
