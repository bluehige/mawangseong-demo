## 3. 구현과 확정 규칙 대조

- 부지: `PlotMask.defense_plot()`의 18×16 직사각형. `(0,0)`은 화면 왼쪽 위, 오른쪽이 +x, 아래가 +y. 마름모 투영 없음.
- 고정 3개: 입구 `(0,7)`, 옥좌 `(8,0)`, 금고 `(8,14)`. 각각 2×2이므로 부지 왼쪽 가운데 / 위 가운데 / 아래 가운데에 위치한다. 모델과 실제 입력 양쪽에서 이동을 거부하고 철거 기능을 제공하지 않는다.
- 주 도로: 입구→옥좌, 입구→금고를 먼저 자동 생성한다. 플레이어 길 그리기 없음.
- 도로 탐색: 비어 있는 2×2 칸의 좌상단 좌표를 탐색하므로 길 폭이 2칸이다. 기본 이동 비용 10, 기존 길 재사용 6, 꺾임 +60, 건물 인접 방향당 +4. 방향과 직선 길이를 탐색 상태에 포함한다.
- 직선 최소 길이: **연속 좌표 3개 이상(이동 2회 이상)** 전에 꺾거나 끝낼 수 없다. 폭 2칸으로 펼친 실제 바닥의 직선은 최소 4칸이다. 기존 길에 이미 포함된 문 앞 2×2 구역은 새 구간이 아니므로 별도의 짧은 가지길을 만들지 않는다.
- 광장 방지: 2칸 길의 정상 L/T/+ 접합은 허용하되, 3×3이 모두 길인 넓어진 구역은 후보와 최종 결과 양쪽에서 거부한다. 최초 시각 확인에서 발견한 인접 가지길의 광장 현상을 이 검사로 보완했다.
- 문: 건물 네 면의 폭 2칸 후보 중 **현재 길의 실제 칸에 가장 가까운 유효 후보**를 선택한다. 동일 거리면 짧고 꺾임이 적은 경로를 선택한다. 막힘·폭·연결 조건을 충족하지 못한 후보는 제외한다. 좌상단 좌표 차이로 문 방향에 편향이 생기지 않도록 실제 문 앞 두 칸과 실제 길 칸의 거리를 비교한다.
- 연결 검증: 모든 길 칸을 입구에서 탐색해 떨어진 조각이 없는지, 옥좌·금고·모든 문 앞 두 칸이 연결되는지 검사한다. 문 앞이 막히거나 최소 간격 1칸이 사라지면 거부한다. 놓는 시점에도 다시 계산한다.
- 수비: 건물 문 바로 바깥 길 칸에 정원만큼 서로 다른 점을 배치한다. 병영 4 / 회복둥지 2 / 함정방 2 / 감시초소 3 / 결계핵 1 = 캡처당 12개. 미끼보물실 2는 별도 직접 검사했다. `DataRegistry.rooms.max_monsters`가 있으면 우선하고, 없는 유형은 기존 시설 정의와 같은 기본값을 사용한다. 고정 3개는 이 설계에서 수비 정원 대상에 포함하지 않았다.
- 오라: 병영 3, 회복 2.5, 함정 2, 감시 4, 결계 3, 미끼 2칸의 반경 메타데이터만 정의했다. 드래그 중 반투명 원을 표시하며 기존 효과·밸런스에 적용하지 않는다.
- 벽: 위·왼쪽 면은 진한 띠, 아래·오른쪽 면은 낮은 연한 띠. 선택한 문 면의 띠는 생략하고 초록색 문 표시를 그린다. 띠 좌표는 자기 건물 내부에만 존재하며 높이·바닥 독립 벽·경계 벽·다른 건물 가림 없음.
- 자유 장식: `PlotDecorationSession.ENABLED=false`로 시작·입력 활성화·런타임 그리기·개별 장식 그리기·팔레트를 비활성화했다. 기존 장식 저장 데이터는 삭제하지 않았다.

### 실제 관리 화면 연결

`ManagementWorkspaceUI.build()`가 플래그를 확인해 `DefenseGrayboxView`를 실제 관리 HUD에 붙인다. `MapBuildService`가 계산한 `root.graph.layout.defense_layout`이 현재 배치의 원본이며 표시·클릭 판정·문·수비 점이 같은 데이터를 사용한다. 놓기에 성공하면 이 런타임 상태를 갱신하고, 실패하면 기존 상태를 유지한다. 별도 그림 파일이나 가짜 캡처 씬을 표시하지 않는다. 테스트 씬은 실제 `GameRoot.tscn`을 띄워 버튼·마우스·키보드 입력을 전달하는 실행 도구다. `GameRoot.gd` 변경 없음.

- 기본 설정: `debug/defense_layout_graybox=false`.
- 켜기: 해당 설정을 켜거나 사용자 인수 `--defense-graybox`를 사용한다.
- A/B/C 버튼 및 키보드, 마우스 드래그/놓기, ESC 취소를 지원한다. ESC는 전역 일시정지보다 먼저 처리한다.
- 플래그를 끄면 기존 관리 화면이 돌아오는 것을 GUI로 확인했다. 새 배치의 저장이나 전투 동선 교체는 이 단계에서 하지 않는다.

### 임의로 정한 가정

- “건물 8개”는 고정 3 + 이동 시설 5의 **총 8개**로 해석했다. 작업 중 선택 질문을 제시했으며 별도 변경 답변이 없어 이 해석을 유지했다.
- 18×16에서 배치 구조를 비교하기 위해 이번 회색 박스의 건물은 모두 임시 2×2다. 기존 정식 건물의 크기·게임 수치·자산을 축소하거나 바꾸지 않았다.
- A는 큰길 양옆 정렬, B는 가지길 접합이 엇갈리는 배치, C는 옥좌·금고 쪽 가지에 상하 분산이다. 여섯 번째 이동 시설인 미끼보물실은 캡처 8개 구성에는 넣지 않고 정원 데이터와 직접 검사만 제공한다.
