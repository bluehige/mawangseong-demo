## 8. 다음 작업 순서

### A. 사용자 실행(유료 경계)

1. 계정에서 모델 사용 가능 여부/청구/사용 조건을 확인한다. `BGM_생성_1.3.0.bat`를 더블클릭한다.
2. 화면의 15곡·15요청·예상$1.20에 동의할 때만 Y를 입력한다. 이때부터 setup의 네트워크 설치와 이후 유료 API 호출이 시작된다.
3. setup 성공 뒤 `Gemini API key (used only by this process)` 보안 프롬프트에 직접 키를 넣는다. 키를 이 인계나 BAT/로그에 붙이지 않는다.
4. 실행 내용은 다음과 같다(이미 키를 받는 run 래퍼 사용, 별도 키 전달 없음).

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/audio/setup_lyria.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/audio/run_lyria.ps1 `
  -LogPath 'C:\Users\blueh\Desktop\진행중인프로젝트\_orchestra\tasks\logs\bgm-1.3.0-run.log' `
  --manifest tools/audio/lyria_v130_manifest.json generate --all --takes 1 `
  --run-id 'v130-<UTC timestamp>' --execute
```

5. 실제 누적 진행/결과 로그는 `_orchestra\tasks\logs\bgm-1.3.0-run.log`. 지금 이 실생성 로그는 작성하지 않았다. 실행기가 첫 실행/취소 때 만든다. run-id와 결과 폴더를 헤드에게 전달한다. 종료 후 pause로 창을 유지한다. 성공해도 게임 연결은 자동으로 하지 않는다.

### B. 부분 실패 재개와 render

1. 로그의 run-id 폴더를 보존한다. 응답 완료한 take의 `source.*`와 `generation.json`을 확인한다. render 실패라면 새 유료 생성 대신 해당 원본을 다시 렌더한다. 요청 도중 오류는 청구 여부를 단정하지 않는다.
2. generate는 같은 run-id의 기존 폴더를 재사용하지 않고 거부한다. BAT 전체 재실행은 완료곡까지 새로 청구할 수 있으므로 남은 asset ID만 골라 `plan --asset <id> ... --takes 1`로 비용을 확인하고, 추가 비용 승인 범위에서 별도 run-id로 `generate --asset <id> ... --takes 1 --execute`한다. 여러 run 폴더/선택 후보의 대응을 기록한다.
3. 이미 generate가 preview를 자동 만든다. 재렌더가 필요할 때만 아래를 사용한다(네트워크 없음).

```powershell
$manifest = 'tools/audio/lyria_v130_manifest.json'
$run = 'tmp/lyria_audio_v130/<actual-run-id>'
& ./tools/audio/run_lyria.ps1 --manifest $manifest render --run $run
# 특정 곡만: render --run $run --asset v130_title_01_lantern_gate --take 1
```

4. 원본을 보존한 채 곡별 preview를 확인한다. 무보컬·독창성·장면 톤·루프 경계·소리 크기·90~150초 최종 길이를 확인한다. 충분한 원본이면 요청 길이-2초가 최종 길이이며, 원본이 짧으면 더 짧다. 90초 미만/무음/클리핑/단절 후보는 미채택한다. 별도 체감 음량 처리 시 preview.json의 SHA와 SOURCE.md 후처리도 일치시킨다.

### C. promote와 출처

청취/채택 판단을 받은 곡만 실제 run/asset/take로 하나씩 승격한다. 기존 출처가 있으면 --force를 자동 사용하지 말고 보존/선택 정책을 확인한다.
