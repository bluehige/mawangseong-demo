## 3. 완료한 작업

### 저장·변환

- `campaign_save_v6.json`이 기본 Continue의 우선 저장이다. envelope version=6이며 기존 profile version=4, 회차·프로필·보상·스토리 및 Update3/4 상태를 유지한다.
- `active_run.plot_state`: `size`, `grade_index`, `unlock_history`, `layout_source`. 자유 배치의 `layout_source.placed_modules`에 원래 module/instance ID, `grid_origin`, `plot_rotation`을 저장한다. 해금 이력에는 단계·stage ID·크기·해금 DAY·사유가 들어간다. 생성 길/이동 그래프는 저장된 배치에서 다시 계산한다.
- v6가 없으면 존재하는 v5→v4→v3→v2→v1 순서로 선택한다. 기존 검증·변환 체인을 거쳐 v6를 새 파일에 기록한다. 구 파일에 복구/격리를 수행하는 기존 `inspect()`를 이관 읽기에 사용하지 않는다. 최신 파일의 손상·미지원 버전을 오래된 체크포인트로 우회하지 않는다.
- 기존 방 ID·시설·배치 참조를 유지하면서 새 부지의 겹치지 않는 좌표로 옮긴다. 문과 입구–왕좌 폭 2 자동 길을 다시 생성한다. 좌표 실패는 방향/좌표만 안전 재배치하며, 방 모듈/필수 앵커가 손상되면 기존 기본 카탈로그의 안전 배치를 사용한다.
- 손상된 v6 배치를 복구하기 전에 원본 바이트를 `.plot_original`에 보존한다. 서로 다른 후속 손상은 `.plot_original.<SHA256>`에 추가로 보존한다. 정상 해금 날짜·구역 이력은 좌표 복구 후에도 유지한다. 진행/프로필 자체가 검증 불가하면 원본을 남기고 Continue를 차단한다.
- 복구된 source가 실제 Continue의 사전 경로 검사와 런타임 그래프에 사용된다. v6가 정상이어도 예전 고정 배치의 잘못된 좌표로 다시 검사/복원하는 경로를 제거했다.
- 임시 쓰기·재독 검증·백업 교체·중단 복구를 연결했다. v6 쓰기 실패 시 앞서 기록한 v2~v5 및 임시/백업 파일도 이전 묶음으로 돌린다. 타이틀 접근성 설정은 v6 프로필만 쓰고 active_run/배치를 유지한다. 새 게임은 현재 설정된 저장 경로를 삭제하여 구 버전에서 v6가 다시 살아나지 않게 한다. 원본 보존 아카이브는 남는다.

### 성 등급·부지

- 새 등급 요구치 없이 M0~M3의 기존 성 진화 4단계를 사용한다: 마굴 30×20 → 소마왕성 36×20 → 요새 마왕성 42×20 → 대마왕성 48×20.
- 기존 진화 날짜와 required flag를 충족한 실제 `_apply_castle_evolution_for_day()`에서만 이력을 추가한다. DAY16 자체로 땅을 주는 규칙은 없다.
- 이미 편집한 방은 커진 중앙 좌표계에 맞춰 각 승급마다 (+6,+6) 평행 이동하며 상대 위치·방향을 유지한다. 새로 열린 방은 기존 footprint를 먼저 예약한 다음 빈 부지를 찾는다. 신규 좌표가 옛 고정 맵 좌표에 겹치지 않는다.
- `PlotSaveState.region_for_cell()`은 이력과 각 단계의 PlotMask로 최초 해금 구역을 판정한다. 승급 후에도 원래 방은 원래 구역으로 분류된다. 이후 의회 1층 목표 집계에서 사용할 수 있다.
- 3언어의 “가로 +6칸” 안내를 관리 피드백과 로그에 연결했다. 진행 차단 사유가 있는 화면은 기존 차단 안내 우선순위를 유지한다.
