## 3. 구현

- `GameRoot._monster_combat_stats()`를 두 전투 생성 경로가 함께 사용한다. 기존 `_scaled_monster_stats()`의 레벨·전문화·승급·집중 준비·교리/칙령·계약·왕관 및 반올림 순서를 유지한다. 굶주림과 저주 인형–실키의 동료 체력 보정도 공통 처리한다. EXP·유대·기억 데이터를 초기화하지 않는다.
- 공통 유닛 신호 연결을 분리해 다운·왕관 HP·피해 분담·유효 회복·심장 첫 제어가 새 지도에서도 기존 기록기에 전달된다. 심장·합동기는 기존 전투 준비/실시간 처리기를 사용한다.
- `CombatSceneController.prepare_battle_systems()`에서 기존 전투 상태 초기화, 심장 준비, 성장 시작 스냅샷, `_active_wave_catalog()`와 `_precombat_defense_modifiers()`를 통한 원정·전선·작전·회차·의회 웨이브 선택을 공유한다. 일회성 원정 보정은 전투 시작 시 소비한다. Approved 고유 생성 시간 흔들림은 유지한다.
- 새 지도 물리 루프에 기존 전선 적·왕관·의회·심장 처리기를 연결했다. 함정 정비 칙령의 재사용 대기시간도 반영한다.
- 날짜 진행의 조기 우회를 제거해 기존 최종전 판정·식량 결산·`GameState.advance_day()`·관리일 진입을 사용한다. 이후 지도 날짜·등급·자원·식량·전문화를 동기화한다. 기존 날짜 진입에서 의회 날짜 상태도 동기화한다.
- 새 게임/다음 회차에서 지도 세션을 비우고 새 회차 자원으로 다시 만든다. 모드 선택 시 전선 DAY4, 의회 DAY1에 맞게 한 번 더 초기화한다. 전투를 시작할 때 과거 DAY30 지도를 되살리지 않는다.
- 옛 DAY3 수련 완료 플래그는 실제 튜토리얼 회차에서만 켠다. 의회 DAY3 승리가 다음 날 진행을 막지 않도록 실제 전투 종료→성장 확인→DAY4 진입을 직접 검사한다.
- 새 지도 전투 버튼과 재도전 요청에 기존 준비 상태·원정/의회 필수 선택 검사를 연결했다. DAY29는 선언→준비 결산→다음 날이며 전투를 생성하지 않는다. 지도 등급이 자동 처리하는 성 강화는 옛 강화 버튼을 별도로 요구하지 않는다.
- 원정·기록실·의회 결정·최후 선언 진입을 복원하고 외부 화면 왕복 시 지갑과 지도 상태를 맞춘다. 몬스터 상세의 레벨·능력치도 실제 공통 계산을 표시한다. 신규 진입 버튼은 식량 경고 아래에 두고 전투 중 숨긴다.
- 의회 목표는 기존 확장 서비스의 임시 안전 시설 방식으로 회복 둥지/금고에 연결한다. `temporary=true / eligible=false`를 명시하며, 별도 확장 부지 방어 업적 자격을 허위로 부여하지 않는다. 시설 문 앞에서는 겹치는 영향권보다 해당 시설의 방 판정을 우선한다.
- 스토리·몬스터 기본값·웨이브 JSON·가격·승률·그래픽/음원 자산 변경 0. 기존 능력치 누락이 복원되므로 전투 결과는 0112와 달라질 수 있다. B04 난이도 수치는 별도 측정 대상이다.
