## 3. 카메라 계산식·실제 수치

`ApprovedPlacementLayout.solve(screen, targets, ui)`가 화면 크기로 계산한다. 이 안전 미리보기는 고정 1920 캔버스 늘이기 대신 실제 창 내부 픽셀을 사용한다. UI 배율은 `u=min(W/1920,H/1080)`, 화면 및 대상과 UI 사이 여백은 `m=8u`다. 8px 여백은 경계 접촉·축소 필터를 위한 이번 구현의 보수적인 가정이다.

필수 대상은 실제 GPT 내부 그림의 **알파가 존재하는 전체 외곽 사각형**으로 읽는다. 빈 투명 캔버스를 필수 대상에 포함하거나 의자/계단 일부를 잘라 검사하지 않는다.

| 대상 | 월드 사각형 x,y,w,h | 근거 |
|---|---|---|
| 옥좌 의자+계단 | 2092,252,423,490 | `interiors/throne.png` 640×640의 알파 외곽 (108,60)~(531,550) + 실제 조립 위치 |
| 입구 문 전체 | 667,1591,359,303 | `interiors/entrance.png` 전체 359×303 + 실제 조립 위치 |

화면 좌표는 `p_screen = z*p_world+t`, 카메라 중심은 `C=((W,H)/2-t)/z`다. 각 대상 `T_i=(a_i,b_i)`의 시작/끝 좌표에 대해 아래를 만족한다.

```text
m - z*a_i <= t <= (W,H)-m-z*b_i

각 UI U_j와 대상 T_i는 다음 중 하나 이상으로 분리:
z*T_i.right  + tx <= U_j.left   - m
z*T_i.left   + tx >= U_j.right  + m
z*T_i.bottom + ty <= U_j.top    - m
z*T_i.top    + ty >= U_j.bottom + m

목표: 위 조건을 만족하는 z 최대화
```

1920×1080의 실제 UI 사각형은 다음과 같다. 상태 문구는 건설 바 내부에 넣었고 조작 안내는 툴팁으로 두어 필수 대상 위의 별도 글씨를 남기지 않았다.

| UI | x,y,w,h |
|---|---|
| 상단 자원 HUD | 24,18,490,66 |
| 단계 탭 전체 | 675,18,570,74 |
| 우상단 보기/닫기 | 1700,18,196,66 |
| 하단 건설 바 | 522,900,876,170 |
| 우하단 미니맵 | 1616,834,280,222 |

대상의 화면 이탈로 정해지는 전체 확대 상한에서 시작한다. 고정 z에서 두 대상의 허용 이동 구간을 교차하고, 각 UI와 겹치게 만드는 이동 사각형 `U_j - z*T_i`를 뺀다. 모든 경계는 `a+b*z` 형태이므로 경계끼리 교차하는 모든 z를 큰 순서로 검사한다. 가능성이 단조롭다고 가정한 국소 탐색이 아니다. 처음 가능한 경계가 최대이며, 부동소수점 접촉을 피하려고 실제 적용에는 `0.00001`을 뺀다. 가능한 위치가 여러 개면 두 대상의 중심이 화면 (0.5W,0.48H)에 가까운 위치를 선택한다.

1920×1080에서는 옥좌 상단이 탭 아래 `92+8=100`, 입구 하단이 화면 아래 `1080-8=1072`에 접근하는 조건이 최대를 정한다. 따라서 `z_max=(1072-100)/(1894-252)=972/1642=0.5919610231`, 실제 `z=0.5919510231`이다. 입구 오른쪽은 건설 바 왼쪽 여백 경계 `522-8=514`다.

## 4. 완료한 UI 보정

- 정보창: 개발용 문 방향/격자 크기 문구 제거. 이름·레벨, 수비 정원, 영향 범위와 기존 시설의 핵심 역할을 표시한다. 강화는 모델의 실제 결과를 미리 계산해 `Lv1 → Lv2`, 병영 `수비 정원 4 → 5명`을 표시하고 비용을 자원 그림+숫자로 보여 준다. 해체는 기록된 지불액에 대한 기존 환불액을 같은 형식으로 표시한다. 강화 제한/부족은 확인 그림 비활성 및 설명으로 표시한다.
- 자동 위치: 건물 발판·벽 높이·내부 그림의 알파 외곽, 모든 상단/하단 UI를 장애물로 사용한다. 정보창 크기만큼 장애물을 확장한 **창의 왼쪽 위 위치 공간**에서 빈 좌/우 영역을 고른다. 원형 메뉴는 그 창도 피한다. 확대가 너무 커 창이나 5개 메뉴를 놓을 공간 자체가 없으면 카메라를 단계적으로 조금 축소해 공간을 확보한다.
- 건설 바: 7개 모두 비용 y좌표를 같은 한 줄로 고정. 자원 그림24px+숫자, 한 자원 칸56px를 사용한다. 금/마나/식량 각각의 부족 여부를 따로 판정하여 부족 숫자만 붉게, 해당 자원 그림은 어둡게 한다. 비용은 기존 실제 카탈로그 그대로다.
- 원형 메뉴: 5개 그림과 짧은 이름 **정보·강화·이동·해체·수비**, 마우스 강조. 거리/각도를 탐색하고 건물·문·다른 건물·정보창·UI·다른 아이콘/이름과 겹치지 않는 배치를 고른다. 가장자리에서는 화면 안쪽의 빈 후보만 허용한다. 원형 후보에 빈자리가 없으면 정확한 빈 위치 공간을 추가 검색한다.
- 단계 탭: GPT 건설/몬스터/전투 그림 + 건설/몬스터 배치/전투 이름. 건설 강조, 나머지는 어두운 비활성 표시만 있다. 클릭 연결·단계 전환은 없다.
- 자원 HUD: GPT 금/마나/식량 그림+숫자. 현재 시험 상태 DAY7·성3과 시험 자원을 표시한다.
- 미니맵: 별도 SubViewport에 **실제 현재 월드 조립 노드를 복제하여 축소 렌더**한다. 가짜 도형이나 고정 목업 그림이 아니다. 건설/이동/해체로 맵을 다시 조립하면 미니맵도 갱신된다. 현재 화면을 GPT 금빛 프레임으로 표시하고 지도 클릭은 해당 월드 위치로 이동한다. 고스트·배치 후보는 미니맵에서 제외한다.
- 취소 후 배치 가능 문구를 지우고, 마우스 설명창도 GPT 흑요석 배경을 사용한다.

스토리·밸런스·게임 데이터·저장 스키마는 변경하지 않았다. 정보의 영향 반경은 앞선 2단계의 시각화 값이고, 시설 역할 문구가 이 미리보기에서 전투 효과를 실행한다는 뜻은 아니다. 수비/전투 연결은 다음 별도 단계다.
