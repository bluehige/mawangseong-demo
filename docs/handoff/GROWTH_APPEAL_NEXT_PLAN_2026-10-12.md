# 스킬 연결 다음 성장 체감 개선 계획

2026-10-12. 현재 단계는 계획 및 인계이며 아래 성장 변경은 아직 구현하지 않았다. 부모 작업은 이 스킬 결과 반환 뒤 별도 턴에서 진행한다. 승인된 범위의 추가 확인은 필요하지 않다.

## 사용자 승인 원문

> 좋아
> 1. 승급의 차이를 행동으로 보여주기. 단순 공격력 상승보다 ‘한 적을 빨리 잡는다’, ‘여럿을 막는다’, ‘아군을 지킨다’처럼 쓰임새가 달라져야 해.
> 2. 전투 후 키운 보람을 보여주기. 피해량만 세면 지원형은 손해야. 실제 기록할 수 있는 회복량·보호 효과 발동·합동기 사용 등을 몬스터별로 짧게 보여주는 쪽을 검토하자.
> 3. 다음 회차에 바꿔볼 이유 남기기. 기존 승급·조합·엔딩 중 ‘이번엔 이쪽으로 키워볼까?’ 할 선택을 연결하는 거야. 보상을 받으려고 같은 플레이를 반복시키는 방식은 피하고.
> 이 추천 순서대로 수정 개발 진행 방향 기획해서 마왕성 수정개발 진행하자. 일단 스킬쪽 완료되면 이쪽으로 가자

## 대표 하나와 조합 하나부터

후속 사용자 지시: ‘당분간 마케팅비용 제로로 준비하고 이번 패치 이후로 홍보 시작. 이번 수정패치가 정말 중요하니 완성도 있게 마무리.’ 검증을 홍보 일정 때문에 생략하지 않고, 출시 차단과 낮은 우선순위 미완을 구분한다. 이 지시는 외부 홍보/Steam 게시 실행 승인이 아니다.

대표는 푸딩의 기존 DAY12 첫 승급 두 분기, 조합은 기존 푸딩+모리 `link_spore_jelly_shelter` 하나를 제안한다. 기존 스킬/외형/VFX/AI가 있으므로 새 기능이 없다는 전제에서 시작하지 않는다. 다음 구현은 먼저 현재 행동을 측정하고 필요한 작은 차이를 더한다. 새 장비 체계를 구현된 것처럼 소개하지 않는다.

| 기존 분기 | 확인된 설계·행동 | 선택 전에 설명할 실제 차이 | 첫 검증 |
|---|---|---|---|
| 성문 방벽 푸딩 / slime_gate_bulwark | entry_anchor, blocker, 기존 방어막 시간+1/감소+.08 | 길목을 맡고 자기 접촉을 버텨 적 접근을 막는 역할 | 같은 적/시드에서 위치 유지·접촉 적 수·왕좌 접근 결과 |
| 구조 연금 젤 푸딩 / slime_rescue_alchemy_gel | ally_guard, support_blocker, 기존 방어막 시간+.5/감소+.05/CD-2, 실제 부상 아군 대상 준비 | 위험한 아군을 찾아 보호하는 역할 | 부상 아군 선택·실제 보호 발동·생존 차이 |

DAY12/Lv3/기존 해금과 비용은 우선 유지한다. 구조형 기존 유대25 조건도 유지. 전열 방벽120G/60M/20악명, 구조형100G/90M/20악명. 초기 훈련은 실제30G→EXP20이고 결산 집중+8/다음날 준비가 이미 있다. 양쪽 행동이 실제로 겹치면 위치/대상 우선순위의 작은 시제품부터 비교한다. 새 이동속도/범위/공격력을 증거 없이 확정하지 않는다. 고블린 thief_hunter 중복은 별도 측정 후 후보로 남긴다.

## 1. 행동 차이의 가시성

승급 선택 화면에 ‘길목을 지킨다’와 ‘다친 아군을 보호한다’를 실제 타겟/AI와 연결한다. 첫 유효 발동에만 짧은 대상/효과 문장을 띄우고, 메뉴·백로그·x1–x3·컷신 off/once/always와의 시간·중복·입력 충돌을 검증한다. 이미 있던 승급 컷신·현재 외형을 재사용한다. 과장된 동작을 연출만으로 넣지 않는다.

완료 기준: 두 분기의 실제 대상/위치 차이가 동일 적 조건에서 재현되고 설명과 일치한다. 차이가 없다면 ‘기존 AI만으로 구분되지 않음’으로 보고하고 최소 AI 조정안을 검증한다. 자연 획득 시점과 실제 사람이 이해하는지는 별도 플레이 확인이다.

## 2. 몬스터별 짧은 실제 기여

기존 battle_contribution_stats와 결산 선택 결과를 확장한다. 한 몬스터에 역할에 맞는 최대2–3개를 보인다. 피해만으로 전체 기여 순위를 만들지 않는다.

| 지표 | 정의 | 금지할 집계 |
|---|---|---|
| 회복 | Unit.heal이 반환한 실제 증가 HP, 효과 출처별 | 오버힐·실패·취소된 준비량 |
| 보호 발동 | 실제 유효 보호 적용1회, caster/source/대상 토큰 | 컷신 재생·준비/중복 콜백 |
| 보호량(구현 가능 시) | 피격 처리의 해당 효과 직전/직후 실제 감소분; 겹친 효과 출처·순서 명시 | 단순시간×평균피해 추정, 여러 시전자 중복 귀속 |
| 합동기 | 실제 커밋된 link 이벤트1회; 참여 몬스터에게 공유 이벤트임을 표시 | 임의 피해 분배, 두 컷신을 두 사용으로 집계 |
| 흡수 | 실제 redirect 대상이 부담한 HP 피해와 보호 효과를 구별 | 대신 맞은 비용 자체를 무조건 막은 피해로 부풀리기 |

effective_healed/damage_redirected와 실제 피해 함수의 출처 전달을 살펴 이벤트 연결부터 한다. 현재 barrier 블록량의 출처별 emitter는 부족하므로 먼저 작은 계측을 구현/검증해야 한다. 세이브는 표시할 실제 이력만 최소 보존하고 과거 저장에 없는 값은 ‘기록 없음’으로 처리한다. 전투 재생·타이틀 반복·불러오기·선택 보상에서 중복하지 않게 한다.

완료 기준: 과회복0, 다중 보호 귀속·만료·무효·redirect 순환·합동기 취소/한 번 커밋이 정확하며 지원형 결과를 사람이 읽을 수 있다. 기존 결산 기본값/성장 선택이 유지된다.

## 3. 다음 회차의 실험 이유

현재 결과를 바탕으로 ‘다음엔 구조형+모리로 보호 기여를 비교’ 같은 선택 제안을 하나 제공한다. 기존 승급·조합·이미 공개된 엔딩 기록에 연결한다. 현재 엔딩 조건을 읽어 맞는 링크만 보여주며 푸딩 승급만으로 엔딩을 보장하지 않는다. 미공개 엔딩 스포일러·새 보상·새 화폐·반복 숙제·새 난이도·새 엔딩은 추가하지 않는다. 새 회차를 강제하거나 확인 없는 자동 시작도 하지 않는다.

완료 기준: 현재 회차의 선택과 다른 한 가지 실제 가능한 선택이 명료하고, 아직 해금되지 않은 조합은 조건을 정확히 표시한다. 저장 재열람과 다시 시작에서 안내 중복이 없고 사람의 자발적 재도전 의향은 사용자 평가로 남긴다.

## 검증·작업 순서

1. 현재 SHA에서 대표 두 분기·한 합동기 행동/기여 baseline. 첫 방어 검토의 DAY2 TUT110 자동 입력 문제는 자연 입력 재현을 먼저 해 진행 차단 여부를 분리한다.
2. 행동 설명/첫 발동 표시, 겹칠 때만 작은 AI 시제품. 동일 맵·동일 실제 적·시드·동일 배치로 비교하고 인간 체감 평가를 요청한다.
3. 출처가 있는 실제 지원 기여 이벤트→짧은 결산 표시→유효/무효/중복/저장 회귀.
4. 기존 해금/조합/엔딩 기록에 다음 선택 한 개 연결, 스포일러·강요·반복 보상 점검.
5. 격리 개발 빌드·실제 GPU 대표 캡처·PASS/FAIL/NOT_RUN·잔여 위험을 반환 후 다른 몬스터 확장 여부 결정.

출시 판단의 우선 게이트: DAY2 반복 입력 정지가 자연 입력에서도 진행을 막는지 확인하고 차단이면 먼저 수정·회귀한다. 저장 실패/취소/타이틀 반복·대화/선택 보상 재실행·스킬 준비와 일시정지 소유권은 해당 수정에 맞춰 회귀한다. 왕관 분기 미연결/남은8은 현재 노출·설명으로 사용자를 오도하는지 별도 판단하고, 미노출 확장 설계를 임의 출시 필수로 넓히지 않는다. 이전 세이브 호환·첫 선택 결과·성장 대표 행동·지원 기여가 증거로 맞으면 그 범위의 검토 빌드를 반환한다. 사람 체감·자연 입력·실제Steam/two-PC 미검증을 출시 PASS로 세지 않는다.

스킬 미연결 여덟 개와 왕관 젤 분기 계승은 별도 전투 기반/설계 수치 결정을 기다린다. 성장 개선이 그 전부의 완료를 의미하지 않는다. 첫 방어 고정 결과와 자동 재플레이는 재미의 증거로 쓰지 않는다. 개인 세이브와 기존 빌드는 보존하고 Steam 공개 배포/원격 Git/새 SDK는 이 범위에 없다.
