# v1.2.6 대중적 제품 품질 검수·개선 계획

## 1. 목표와 고정 기준

- 검수 기준 출시본: `v1.2.5@f757ffa9f9e962158f2123856c8568a3163ecb6c`
- 완성 목표: `v1.2.6`
- 전체 범위: 타이틀부터 DAY 30까지 정식 출시본 전체
- 합격 기준 플랫폼: Windows PC
- Web·모바일 등: 호환성 테스트 범위이며 품질 합격 기준은 아님
- 핵심 매력 우선순위: `전술 지휘 쾌감 → 몬스터 애착 → 행정·상황 코미디`
- 기본 분위기: 계속 가볍게 유지하되 마왕의 후반 성숙 장면에서만 진지함을 강화

## 2. 실행 원칙

실행 순서는 고정한다.

1. 핵심 전투·UI
2. 대사·그래픽
3. 전체 캠페인

각 단계는 반드시 `검수 → 원인 분류 → 수정 → 영향 범위 재검수 → 단계 게이트`를 마친 뒤 다음 단계로 넘어간다. 자동 코드 테스트는 회귀 안전망으로만 사용하며 플레이 감각·가독성·미학·대중성 판정을 대신하지 않는다.

Codex는 세 단계를 모두 통과한 결과를 `v1.2.6` 완성품으로 판정해 사용자에게 전달한다. 사용자와 지인의 플레이테스트는 전달 이후 별도로 진행하며, 새 피드백은 후속 개선 주기로 접수한다.

## 3. 에이전트 운영 구조

### 검수 지휘

| 역할 | 책임 |
|---|---|
| `Audit Lead / Gatekeeper` | 동일 SHA 고정, 이슈 원장 통합, 심각도 판정, 수정 우선순위와 단계 통과 결정 |
| `Evidence Capture Agent` | 화면·DAY·행동별 재현 절차, 전후 캡처, 시간 측정, 오디오 표본과 빌드 SHA 보존 |
| `Implementation Agent` | 원인이 확인되고 해당 단계 범위에 속하는 수정만 수행하는 단일 writer |

동시 실행은 지휘 에이전트와 읽기 전용 전문 에이전트 최대 3개로 제한한다. 같은 제품 파일을 여러 에이전트가 동시에 수정하지 않는다.

### 역할별 AI 검수단 8명

| ID | 구성 | 주 검수 관점 |
|---|---|---|
| `N1` | 전략게임 초보 | 첫 화면 이해, 설명 없이 다음 행동 찾기, 조작 불안 |
| `N2` | 전략게임 초보 | 명령 대상·결과 이해, 실패 후 복구 가능성 |
| `N3` | 전략게임 초보 | 정보량·피로도·난이도 상승·장기 플레이 이탈 지점 |

각 에이전트는 다른 보고서를 보기 전에 독립 1차 판정을 제출한다. 이후 Gatekeeper가 공통 결함과 역할별 차이를 합친다.

## 4. 단계별 검수 계획표

### 1단계 — 핵심 전투·UI

| 전문 에이전트 | 구체적 검수 |
|---|---|
| `Combat Responsiveness Agent` | 이동 시작·정지·방향 전환, 경로 정체, 충돌·왕복 진동, 공격 전환, 게임 속도별 체감 |
| `Command Reliability Agent` | 클릭부터 대상 확정·수락·행동·결과까지 추적, 오대상·묵살·중복 입력, 수행 불가 피드백 |
| `Tactical AI Agent` | 역할별 표적 선택, 위험 대응, 아군 구출·후퇴·복귀, 명령과 자율 AI의 우선순위 |
| `UI/UX Agent` | 한 화면 한 목적, 상시 핵심 행동 최대 3개, 중요 행동 2단계 이내, 선택 상태·비활성 이유·취소 가능성 |
| `Combat Audio Agent` | 명령 수락·거부음 구분, 경고음 인지, 타격감, BGM·효과음이 판단을 가리는지 |

필수 장면은 v1.2.5에서 실제 존재하는 첫 전투, 다중 표적·경로 전투, 시설 또는 핵심 목표 위기, 고밀도 후반 전투를 고정 SHA에서 선정한다. 추측한 v20 장면을 대신 사용하지 않는다.

필수 통과 조건:

- 유효 명령은 입력 후 최대 0.3초 안에 첫 가시 반응을 보이며 명령 지속시간 동안 평상시 AI보다 우선한다.
- 유효 명령의 대상과 실제 반응 대상이 일치하고, 설명 없는 묵살·오대상이 없다.
- 수행 불가 시 대상 근처 이펙트와 비모달 소형 알림으로 `거부 이유 + 가능한 해결 행동`을 보여 준다.
- AI는 역할에 맞는 이유 있는 판단을 하되 사용자 명령을 독단적으로 뒤집지 않는다.
- 초보자가 명령 대상·상태·결과와 다음 행동을 별도 설명 없이 찾을 수 있다.
- Windows PC 대표 해상도에서 핵심 텍스트·상태·대상이 즉시 구분된다.
- 수락음·거부음·위기 경고가 서로 구분되고 핵심 화면 판단을 방해하지 않는다.

단계 산출물: 명령 추적표, 이동·AI 재현표, UI 우선순위 지도, 오디오 큐 표, 전후 캡처, 수정·재검수 결과.

### 2단계 — 대사·그래픽·오디오

| 전문 에이전트 | 구체적 검수 |
|---|---|
| `Korean Narrative Editor` | 데이터와 코드에 실제 노출되는 전체 문구 인벤토리, 자연스러운 한국어, 중복·설명문·길이·타이밍 |
| `Character Voice Agent` | 마왕·바티·핵심 몬스터 화자 고유성, 몬스터 애착, 가벼운 코미디와 후반 성장 일관성 |
| `Art Director` | 캐릭터 실루엣, 적아·역할 식별, 팔레트·광원·화풍·디테일 밀도, UI와 배경의 조화 |
| `Technical Art QA Agent` | 원본 노이즈, 알파·크롭, import·압축, 축소 필터, 정지·이동 중 계단·shimmer 원인 분리 |
| `Audio/Mix Agent` | BGM·효과음 반복 피로, 장면 감정과의 일치, 경고·대사·전투음 마스킹, 음량 급변 |

검수는 원본만 보지 않고 실제 Windows 게임 표시 크기에서 수행한다. 그래픽 결함은 `원본 → 후처리 → import·압축 → 축소·필터 → 화면 합성` 순으로 원인을 나누며, 원인 확인 전 일괄 재생성하지 않는다.

필수 통과 조건:

- 화자명을 가린 대사 표본에서 핵심 화자 귀속률 75% 이상.
- 몬스터는 배치·명령 수락/거부·위기·승리·패배에 짧게 반응하며 UI 설명문을 대신 읽지 않는다.
- 같은 문장을 다른 화자 이름으로 바꿔도 성립하는 교환 가능 대사를 핵심 표본의 20% 이하로 낮춘다.
- 대사창·전투 대사가 핵심 HUD 판단을 가리거나 읽기 전에 사라지는 사례가 없다.
- 실제 표시 크기에서 적아·역할·캐릭터를 즉시 식별하고, 명백한 자글거림·알파 테두리·이동 중 shimmer가 없다.
- 오디오가 장면과 행동을 강화하며 반복 피로·클리핑·핵심 신호 마스킹이 없다.

단계 산출물: 런타임 대사 원장, 화자별 voice bible, 대사 수정표, 자산 원인 매트릭스, 실제 크기 정지·이동 비교판, 오디오·믹스 수정표.

### 3단계 — 타이틀부터 DAY 30 전체 캠페인

| 전문 에이전트 | 구체적 검수 |
|---|---|
| `Campaign Runner` | 새 저장으로 타이틀·온보딩·관리·전투·결산·엔딩까지 DAY별 완주와 진행 차단 확인 |
| `Onboarding/UX Continuity Agent` | 새 기능 등장 시점, 설명과 실제 행동의 일치, 화면·용어·조작 일관성 |
| `Progression/Tactics Agent` | 난이도 상승, 선택의 의미, 단일 정답 반복, AI·명령·자원 운용 깊이 |
| `Narrative Continuity Agent` | 몬스터 애착 누적, 농담 반복 피로, 마왕 성장, 후반 진지함과 결말 회수 |
| `Release Candidate Gatekeeper` | 모든 DAY 이슈·P3 잔여·회귀·버전 표시·Windows 완성품 증거 통합 |

8개 역할 에이전트는 각각 깨끗한 저장 상태에서 타이틀부터 DAY 30까지 독립 관점으로 완주한다. 모든 DAY의 관리·전투·결산 전환을 기록하고, 타이틀·DAY 1~3·5·10·15·20·25·29~30은 공통 비교 지점으로 삼는다.

필수 통과 조건:

- 진행 차단·저장 손상·필수 기능 미설명·명령 불능이 없다.
- 초반 학습, 중반 변주, 후반 난이도와 서사 상승이 끊기지 않는다.
- 앞 단계에서 통과한 전투·UI·대사·그래픽·오디오 품질이 DAY 30까지 유지된다.
- 역할별 검수단이 반복 피로, 불필요한 기능 과점유, 후반 정보 과부하를 핵심 결함으로 남기지 않는다.
- Windows PC 완성품이 `v1.2.6`으로 일관되게 식별되고 최종 전달 체크리스트를 충족한다.

단계 산출물: DAY 1~30 캠페인 매트릭스, 8개 독립 보고서, 통합 이슈 원장, 최종 회귀표, Windows 완성품과 완료 판정서.

## 5. 공통 단계 게이트

| 기준 | 통과 조건 |
|---|---|
| 심각도 | 재현 가능한 P1/P2 0건 |
| 역할별 판정 | 독립 검수단 8명 중 6명 이상 통과 |
| 전문 관점 보호 | 디자인 담당 2명 또는 스토리 담당 2명이 같은 핵심 결함을 지적하면 보류 |
| P3 | 경미한 다듬기는 이슈 원장과 최종 알려진 항목에 남기고 다음 단계 진행 가능 |
| 회귀 | 수정 영향 장면과 해당 단계 대표 장면 재검수 통과 |

P1은 진행·저장·조작 또는 핵심 명령을 막는 결함이다. P2는 대중적 이해·전술 신뢰·가독성·화자/화풍 일관성을 반복적으로 훼손하는 핵심 품질 결함이다. P3는 진행과 핵심 이해를 막지 않는 미세 다듬기다.

## 6. 이슈와 증거 형식

모든 이슈는 다음을 남긴다.

- 이슈 ID, 단계, DAY·화면·행동
- 고정 빌드 SHA와 실행 환경
- 기대 행동과 실제 행동
- 재현 횟수와 심각도
- 화면·영상·오디오 증거
- 연결된 사용자 의도 ID
- 원인, 수정 경로, 전후 결과
- 8개 역할 판정과 Gatekeeper 결론

명령 성공률이나 승리율 하나로 전투 체감을 통과 처리하지 않으며, 파일 존재·해시·자동 테스트만으로 대사·그래픽·오디오 품질을 통과 처리하지 않는다.

## 7. 최종 완료 정의

1. 세 단계가 순서대로 공통 게이트를 통과한다.
2. P1/P2가 0건이고 허용된 P3가 명시돼 있다.
3. Windows PC용 `v1.2.6` 완성품과 DAY 1~30 증거가 같은 최종 SHA를 가리킨다.
4. Codex가 완료 판정서와 완성품을 사용자에게 전달한다.
5. 이후 사용자·지인 테스트에서 들어온 피드백은 기존 완료를 소급해 조작하지 않고 새 피드백 주기로 추적한다.
