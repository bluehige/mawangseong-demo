## 3. 완료한 작업과 실제 호출

### 건설의 시각적 결함 보완

- ward_core를 foundation_marks와 분리했다. 실제 저장소의 단계 3/4 NW 수호핵 자산을 사용한다. 빈 건설 구역은 실제 NW foundation 자산을 사용한다.
- 카드·고스트·실제 설치물은 ModuleGraph 시설 구성과 QuarterDungeonRenderer의 동일 stage/facing/배치 계산을 공유한다. 수호핵은 실제로 존재하는 NW 방향으로 고정했다. 미제작 방향을 같은 그림의 복사본으로 등록하지 않았다.
- 하단 도구함에 후보 건물이 가려지면 현재 canvas 변환에서 필요한 만큼 지도를 이동해 전체 경계를 보여준다. 화면을 떠나면 원래 지도 변환을 복원한다.
- **추가로 발견한 실제 결함:** 고스트 Control의 크기가 0×0이어서 지도 이동 뒤 visible=true와 그리기 호출이 있어도 화면에서 사라졌다. 실제 건물 경계를 Control 위치/크기로 지정하고 로컬 그리기 좌표를 보정했다.
- 논리적 자산 일치 검사만으로 놓쳤던 결함이다. 이제 유효 드래그·줌/이동·6개 해상도/글자 조합·18개 후기 시설 경우에서 고스트만 숨긴 실제 렌더 이미지와 비교하는 26개 픽셀 검사를 수행한다.
- 예시: watch_post 드래그 2,617개, 줌/이동 3,577개 표본 픽셀 변화. 수치는 해당 실행 로그 기준이며 성능 수치가 아니다.
- 입력→후보→검토→기존 _confirm_build_preview / _evaluate_facility_placement / _change_room_facility→기존 Undo 경로를 유지했다. 화면 보정은 자원·건물·길·몬스터·저장·튜토리얼 완료를 변경하지 않는다.

- GameRoot → ManagementSceneController.build_monster_ui → MonsterWorkspaceUI.
  실제 얼굴·이름·레벨·현재 방을 먼저 표시하고 선택 동료의 훈련 전후 EXP/능력치, 특화, 진화 후보와 비용을 스크롤 목록으로 보여준다.
- 작은 기억 아이템 아이콘 대신 실제 캐릭터/진화 초상화를 찾도록 monster_portrait_path를 연결했다. 긴 기억 기록은 내용만큼 늘어나는 카드로 표시한다.
- GameRoot → ManagementSceneController.build_result_ui → ResultWorkspaceUI / V122CombatResultViewModel.
  왕좌 피해·금화 손실·생존·시설 중단 등 실제 기록을 “관찰”로 표시한다. 없는 기록은 “기록 없음”이며 패배 원인을 단정하지 않는다. 시설 중단 횟수를 서로 다른 방의 수로 오인하지 않는다.

- 관리 전용일/전초기지 결과가 이전 방어의 보상을 표시하지 않도록 해당 결산 기록을 사용한다. 결과 버튼은 화면 상태와 성장 선택을 재확인해 오래된 버튼 콜백이 다음 날을 중복 진행하지 못한다.
- 훈련 금화 30/EXP 20은 기존 값 그대로 공통 상수로 사용한다. 비용·성장 계산·보상 지급 규칙을 새로 만들지 않았다.

### 전투와 필수 메뉴

- 상시 명령 3개(집결·집중·비상 후퇴)와 선택 시설 가동을 분리한 기존 실행 계약을 유지한다. 대상 클릭은 바로 실행하며 새 확인창을 추가하지 않았다.
- 왕좌/방어 진행 수치의 높이 부족, 작은 속도 버튼과 선택 유닛 정보를 보정했다. 새 도구함의 전장 경계·겹침 계약을 맞췄다.
- **직접 입력에서 발견한 결함:** 전투 일시정지 메뉴의 계속 버튼을 누르면 지도 클릭이 먼저 방을 선택해 HUD와 버튼을 재생성했다. pause_menu_open 중 전장 입력을 막아 실제 계속/설정 버튼으로 조작할 수 있게 했다.
- TitleWorkspaceUI: 실제 유효 저장이 있으면 이어하기 우선. 새 게임 확인에서는 배경 버튼을 비활성화하고 취소를 먼저 포커스한다. Tab 순환/Enter 취소/ESC가 기존 저장 파일의 바이트를 보존함을 검사했다.
- RaidWorkspaceUI: 임무 선택→상세→파견 대원 전체 목록으로 정리했다. 실제 잠금·필요 인원·비용·보상을 표시하고 기존 실행을 한 번만 호출한다. 복귀 버튼은 실제 후속 대화/안내를 포함하는 “방어 준비”로 표시한다.
- RequiredPreparationUI 및 Update4CouncilDecisionOverlay: 필수 특화·첫 원정·왕관·최종 선언의 중요 선택을 숨기지 않는다. 모든 선택지를 스크롤/키보드로 접근하고 실제 비용 부족 이유를 표시한다. 왕관 대안은 기존 인장 비용을 미리 평가한다.
- 대화는 실제 폰트로 본문 높이를 측정하고 긴 내용은 스크롤한다. 포커스된 자동/다음 버튼의 Enter를 전역 다음 대사 입력이 가로채지 않게 했다. 전투 대화의 정지/기존 속도 복귀 계약은 유지했다.
- 공통 UIUXTheme과 HUD 버튼 상태를 연결했다. 독립 씬 8개 및 전초기지 씬에도 기존 override를 교체했다. 전초기지 깃발 HP의 기본 회색 표시를 공통 색상으로 바꿨다.
