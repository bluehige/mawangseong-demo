## 요청과 범위

- 요청 사항: 게임의 핵심 재미인 건물 배치와 몬스터 육성이 더 명확하고 쉽고 간단하게 수행되도록 예시 이미지를 수정하고, 그 화면을 기준으로 UI를 수정할 수 있는 계획을 만든다.
- 완료 조건: 실제 그래픽 자산과 실제 시설·성장 데이터를 사용한 건물 배치, 몬스터 육성, 수비대 배치 3개 화면과 정확한 구현 순서를 만든다.
- 이번에 하지 않은 일: 사용자 시안 승인 전 게임 UI 코드, scene, runtime 자산, 게임 데이터, 저장 schema, 밸런스와 Web 배포는 변경하지 않는다.

## 완료한 작업

- 구현·문서:
  - 기존 정식판 UI 계획에서 준비 단계만 핵심 재미 중심 구조로 교체하는 수정 계획을 작성했다.
  - `건물 배치 → 몬스터 육성 → 수비대 배치`를 상위 `배치` 상태 내부의 세 단계로 정의했다.
  - 현재 세 명은 별도 편성 검색 화면 없이 바로 사용하고, 보유 수가 출전 한도를 넘을 때만 편성 서랍을 열도록 유지했다.
- 데이터·밸런스:
  - V20 시설 5종의 현재 비용·효과와 고정 경로 동작을 확인했다.
  - `data/specializations.json`의 푸딩·곱·핀 실제 두 분기와 `facility_synergy`를 확인했다.
  - 현재 DAY 1~5 계약이 몬스터 성장을 금지한다는 충돌을 기록하고, 화면 구현보다 계약·세션·저장 연결을 먼저 수정하도록 계획했다.
- UI·그래픽·오디오:
  - 실제 연결형 지도, 푸딩·곱·핀 초상과 기존 시설 prop으로 3개 정적 화면을 제작했다.
  - 시설 선택 시 유효 칸, 지도 미리보기, 효과 범위와 비용 전후를 한 화면에 표시했다.
  - 육성 화면에서 실제 두 분기와 추천 건물을 동시에 비교하도록 했다.
  - 배치 화면에서 설치 건물과 몬스터 역할 궁합을 같은 지도에 표시했다.
- 저장·호환성:
  - 코드는 수정하지 않았다.
  - 후속 구현에서 V20의 하드코딩된 역할을 선택한 특화·레벨·EXP·유대·훈련 횟수 저장으로 교체해야 함을 계획에 명시했다.

## 자산 기록

새 runtime 그래픽이나 오디오는 없다.

- 생성 모델: GPT 내부 이미지 생성은 방향 탐색에만 사용
- 생성 원본과 `SOURCE.md`: 저장소에 추가하지 않음
- 런타임 자산: 추가·수정하지 않음
- 실제 연결 확인: 정적 HTML이 저장소의 지도, 캐릭터 초상과 시설 prop을 직접 참조해 렌더되는 것을 확인

바리케이드 전용 prop은 현재 없다. 시안은 기존 성문 prop을 임시 후보로 사용했으며, 구현 전 재사용 또는 전용 자산 신규 제작을 사용자에게 승인받아야 한다.
