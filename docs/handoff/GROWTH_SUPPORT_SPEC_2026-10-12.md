# 승인된 성장 대표 개선 계약

기준 제품 efc7aa12, 문서2f69f2a. 기존 승인 GROWTH_APPEAL_NEXT_PLAN의 푸딩 DAY12 두 분기·푸딩+모리 합동기·기존 다음 회차 제안만 구현한다. 전체 재미/밸런스 PASS가 아니다.

먼저 변경 없는 기본 행동 측정 완료: growth-baseline2.log PASS9/0. 같은 위치/부상 아군/실제 explorer에서 성문 방벽은 자기 shield6s/reduction.48/incoming100→HP52, 구조형은 부상 고블린 shield5.5s/.45/100→55. 적이 없는 동일 장면에서 각각 입구 방어선(691.2,384.64), 부상 아군 회복실(1336.32,330.88) 이동 목표가 다르다. 통제 DAY12/LV3/유대25 fixture이며 자연 획득·승률·재미 측정이 아니다. 첫 baseline은 테스트의 잘못된 Unit property 접근으로 script error였으며 PASS로 세지 않는다.

1. 기존 DAY12/LV3/유대25/두 분기 비용/스킬·AI·외형·적 수를 유지한다. 선택 설명에 실제 대상과 이동 차이, 왕좌 위협/수동 명령이 우선이라는 조건을 표시한다. 기존 행동이 구분되므로 이번 대표에는 새 AI·공격력 시제품을 넣지 않는다. 고블린 중복/적 없는 대기 압축은 별도 실제 측정 없는 변경을 확정하지 않는다.
2. 푸딩 기본 shield가 실제 target의 timer 또는 reduction을 늘린 commit에만 보호 적용1회와 첫 유효 발동 안내를 기록한다. 준비·무효 취소·이미 더 강하고 오래 남은 shield는0. 기존 메뉴 중단은 유효한 accepted action을 한 번 확정하므로 실제 효과가 생기면 기록한다. 안내는 전투마다 actor 첫 적용만, 전투 시계 deadline 기준5초 simulation, 입력을 가로채지 않고 메뉴/컷신 Skip을 덮지 않는 위치. 이 숫자는 HP 보호량 추정이 아니라 실제 적용 횟수다.
3. 기존 source-aware effective_healing/shield_absorbed를 재사용한다. redirect는 보호자가 실제로 잃은 HP만 별도 비용으로 집계하고 막은 피해로 표시하지 않는다. 실제 Duo.activate 성공 commit의 참여 actor에게 같은 공유 사용1회를 표시하며 둘을 합쳐2회 사용으로 만들지 않는다. 동일 used/cancelled 재시도는0. 결과에는 최대3개 지표, 순위·DPS·추정 방어량 없음.
4. 위 표시 자료는 기존 성장 Dictionary 행에 bounded plain integer snapshot으로 저장한다. Node/Ref는 저장하지 않고 새 파일/슬롯/Cloud 등록 없음. 과거 행에 필드가 없으면 기록 없음. 현재 언어로 재표시한다. 새 전투의 카운터는 기존 battle reset을 따른다.
5. 최종 승리 결과에서 현재 푸딩 분기와 다른 기존 분기 한 가지를 정적 문장으로 제안한다. 모리 보유/기존 계약과 기존 합동기 해금 조건(각자 유대45·기억1·함께 출전3일·역할조합5)은 실제 카탈로그에서 읽는다. 이미 본 일반 엔딩만 기존 requirements와 실제 현재 metrics로 판정해 조건 충족 여부를 표시하고, 최종 확정은 전체 엔딩 판정에 따른다고 명시한다. 숨은 엔딩명·보장·새 보상·화폐·강제 새 회차·반복 숙제는 추가하지 않는다. 새 팝업 없이 결과 재열람에서 한 번 그리는 안내다.

검증은 변경된 commit/지표/실제 결과·승급 UI/컷신 off-once-always·취소/중복·pause 및 배속·기존 저장 왕복 경계에 제한한다. efc7aa12의 지원 숙련/PCK/continuity 등 통과 결과는 SHA/범위를 보존해 재사용하고 전체 QA를 반복하지 않는다. 개인698와 기존9개 구현 패키지를 보존해 비공개 새 검토 빌드까지만 진행한다. 인간 체감·자연 전체 캠페인·현재 Steamworks/two-PC는 NOT_RUN이다.
