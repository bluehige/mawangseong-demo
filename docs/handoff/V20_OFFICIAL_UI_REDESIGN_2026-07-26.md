## 요청과 범위

- 요청 사항: 현재 게임의 이름·화면·그래픽·기능을 임의로 바꾸지 않고, 정식 버전에서 사용할 화면 구조를 그래픽적으로 다시 설계한다.
- 추가 조건: 앞으로 캐릭터가 여러 명 추가돼도 사용할 수 있는 편성·배치 구조를 계획한다.
- 완료 조건: 기존 화면의 무엇을 유지·이동·삭제할지 표로 고정하고, 타이틀부터 결과까지 실제 자산을 사용한 예시 화면을 만든다.
- 이번에 하지 않은 일: 게임 UI 코드, scene, 데이터, 밸런스, 저장 schema, 런타임 자산과 Web 배포 변경.

## 바로잡은 내용

- 공식 제목 `마왕님, 마왕성은 누가 지켜요?`와 기존 메뉴를 그대로 유지한다.
- 앞서 제안한 `2.0 친구 테스트` 별도 타이틀 카드를 폐기했다.
- 가짜 캐릭터와 임의 이름을 쓰지 않고 푸딩·곱·핀·로로의 실제 초상을 사용했다.
- 캐릭터 3명 고정 세로 목록을 폐기하고 `보유 캐릭터 → 출전 명단 → 지도 배치` 3단계 구조로 교체했다.
- 현재 3명은 자동 편성해 추가 화면을 만들지 않고, 보유 수가 출전 한도를 넘을 때만 편성 서랍을 연다.
- 현재 지도 4구역의 2슬롯을 기준으로 동시 출전은 최대 8명, 보유 목록은 30명 이상도 스크롤로 처리하도록 계획했다.

## 완료한 작업

- 기존 타이틀·메뉴 callback, 저장 보호, 준비 지도, 고정 경로, 전투 렌더러, 실제 캐릭터·적·시설 후보 자산을 다시 확인했다.
- 정식판 시각 원칙, 화면 공통 좌표, 화면별 현행→신규 구조와 구현 순서를 새 계획서에 기록했다.
- 실제 저장소 자산으로 타이틀, 침입, 시설, 편성, 배치, 카운트다운, 전투, 결과 8개 화면의 정적 HTML 시안을 만들었다.
- HTML을 Chrome에서 `1280×720` PNG로 각각 렌더링해 글자 잘림, 자산 누락과 화면 구성을 확인했다.
- 이전 계획 문서에는 폐기된 초안임을 표시했다.

## 그래픽과 자산

- 타이틀 배경, 연결형 지도, 전투 배경, 푸딩·곱·핀·로로 초상과 실제 monster/enemy sprite를 사용했다.
- 시설 화면은 저장소의 `assets/props/v3/` 자산을 V20 시설에 재사용할 수 있는지 보여주는 제안이다.
- 시설 prop은 현재 V20 데이터에 연결되지 않았으므로 구현 때 시설 ID별 연결을 별도로 확인해야 한다.
- 새 런타임 이미지와 생성 원본은 추가하지 않았다.
- AI 이미지 생성 결과는 방향 탐색에만 사용했고, 최종 구조 시안은 실제 저장소 자산으로 다시 제작했다.
