## 3. 완료한 작업

- `PlotPlacementSession`은 후보 좌표마다 기존 MapBuildService/AutoRoadBuilder로 건물 간격·부지 경계·모든 문과 입구–왕좌 폭 2 길을 재계산한다. 같은 칸·방향의 포인터 이동은 재계산하지 않는다. 유효 후보는 녹색, 불가는 빨강이며 길 생성 실패 때는 기존 길을 빨강으로 표시하고 설치를 거절한다.
- U5-B 실제 팔레트와 상세 패널을 재사용한다. 후보 그래프의 기존 게임 그림으로 고스트를 만들고, 기존 비용·효과·고유 시설 이전 위치 경고를 표시한다. 드롭/위치 클릭 즉시 설치이며 별도 확정 단계는 추가하지 않았다.
- 빈 부지 설치는 기존 열린 빈 건설 구역을 그 좌표로 이동하여 설치한다. 열린 시설 구역 수·고유 시설 제한·비용·강화·HP·정원·효과 계산은 유지한다. 시설 수를 늘리는 새 밸런스 규칙은 만들지 않았다.
- 상세 패널의 이동·회전·철거와 미리보기 회전/R을 연결했다. 방향은 원본/90도 두 상태이며 모듈의 크기·바닥·이동 칸·문 소켓도 회전한다. 이동·회전은 HP/강화/수비대/자원을 보존한다. 입구는 이동 불가, 왕좌는 이동 가능·철거 불가다. 철거는 기존 빈 건설 구역/환급 없음 규칙을 재사용한다.
- 기존 한 번 되돌리기에 runtime plot source를 함께 보관하여 위치·방향·시설·자원·수비대를 복원한다. 취소는 지출하지 않으며 바로 앞 설치의 되돌리기를 유지한다.
- 마우스와 실제 ScreenTouch/ScreenDrag 입력을 지원한다. 취소·되돌리기·이동·회전·철거 버튼은 손가락의 눌림과 놓기를 같은 버튼에서 확인한다. 스크롤 잘림·다른 손가락·취소 이벤트를 구분하고, 터치에서 생성된 마우스 중복 이벤트를 억제한다. 관련 [Godot 공식 InputEvent 문서](https://docs.godotengine.org/en/stable/classes/class_inputevent.html)의 DEVICE_ID_EMULATION과 실제 4.6.3 실행으로 확인했다.
- S3-03: 부지 내 온전한 건물 면적과 1칸 간격을 만족하는 후보 중심을 강조한다. 최종 가능 여부는 후보의 자동 길 검증으로 판정하여 고스트에 표시한다.
- S3-04: 감시초소의 실제 전투 탐지 계산을 재사용한다. 구역 기반 전투는 FacilityZoneEffectResolver의 detection/enemies 결과와 전투의 방→구역 매핑, 그 밖에는 기존 인접 방 계산을 사용한다. 비활성 초소의 범위는 표시하지 않는다. 표시 결과와 전투 판정을 모든 실제 방/통로 ID에서 비교했다.
- 첫날 전열/후열 대상은 현재 방어 구역과 시설 연결에서 찾는다. 안내·터치·행동 판정·전후열 대사를 같은 대상 집합에 연결했다. 팔레트 카드, 고스트, 자동 길, 입구/왕좌의 현재 위치를 안내 대상으로 등록하고 보조 강조를 표시한다.
- 전체 13단계, 첫날 이름→왕좌 설명→곱 선택→전후열 배치→성장 확인의 기존 ID·순서·stage·block_until을 유지했다. 건물 설치를 새 필수 행동으로 추가하지 않았다. ko/en/zh_CN 각각 본문·조작 안내·입구/왕좌 표시 7키를 변경했다.
