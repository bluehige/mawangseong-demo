# 마왕성 UI/UX 현재 상태 진단 — 2026-10-14

## 요약: 덜 만든 느낌의 핵심 원인 5가지

1. **정보가 실제로 사라진다.** 데스크톱 건설 팔레트에서 시설 이름 5개, 성장 화면에서 동료 이름 3개와 ‘훈련’ 제목이 표시되지 않는다. 터치 성장에서는 18개 라벨이 `visible_lines=0`이다. 작은 글씨 문제에 앞서 글자와 상자의 높이가 맞지 않는 결함이다. 근거: 70, 76, 123. 사용자 #7, #16, #21, #23.
2. **일러스트와 메뉴가 하나의 장면으로 구성되지 않는다.** 타이틀은 왼쪽 거대 패널, 오른쪽 동료 카드 세 장이다. 대화는 매번 왼쪽 한 초상만 갈아 끼우고 위쪽 대부분을 비운다. 사용자 기준의 중앙 메뉴·다수 동료·좌우 참여자 유지와 다르다. 근거: 03, 11, 13. 사용자 #1, #3, #34.
3. **꾸민 테두리가 정보의 중요도보다 강하다.** 주요 행동, 보조 메뉴, 카드, 튜토리얼 마스크까지 비슷한 금색/보라색 테두리를 사용한다. 터치에서는 큰 테두리 버튼이 화면을 압도하고, 어둡게 가려야 할 튜토리얼 마스크의 경계도 패널처럼 보인다. 근거: 18, 49, 121. 사용자 #2, #6, #21.
4. **큰 빈 공간과 작은 핵심 정보가 공존한다.** DAY1 침입 정보는 1108×698 패널에 적 한 줄뿐인데, 경로·목표 설명은 14–15px다. 후기 관리의 공지 안에는 10–12px 텍스트가 있다. 공간 부족보다 배분과 위계의 문제다. 근거: 17, 76–78. 사용자 #5, #21.
5. **화면별 표현 체계가 다르다.** 본성은 입체 지도, 상층은 도식 카드, 전초기지 전투는 검은 바탕의 일직선이다. 스킬 컷신은 단색 큰 사각형과 기본 Button이며, 평소 HUD·지원 알림이 남는다. 전부 기본 Godot 컨트롤이라는 진단은 부정확하지만 스킨·조작·그림의 통일성은 부족하다. 근거: 99, 104, 117, 126, 141. 사용자 #2, #20, #21.

## 요약: 복잡한 UX의 핵심 원인 5가지

1. **결정 사이에 대화 화면이 반복된다.** 새 게임부터 첫 결과까지 오프닝 4, 관리 진입 8, 배치 반응 2, 전투 직전 8, 전투 중 6, 승리 후 8번의 진행 클릭을 관찰했다. 총 36번이다. 배치·방어라는 실제 선택보다 진행 버튼을 누르는 비중이 크다. 사용자 #3, #4, #30.
2. **성장의 네 의미가 흩어져 있다.** 훈련=금화로 영구 EXP, 집중성장=결과에서 무료 EXP+다음 방어 효과, 특화=별도 영구 행동 선택, 진화=후기 모습/역할 변경이다. 결과의 ‘성장 확인’은 훈련 화면을 열지 않는다. 사용자 #13–18, #37.
3. **관리 모드와 대상 선택이 중첩된다.** 건설/수비대/전술 탭 → 카드 선택 모드 → 지도 대상 → 검토 → 확정, 여기에 방 상세·방 지침·전역 지침·예상 경로가 따로 있다. 다른 동작을 시작하려면 모드를 끝내거나 패널을 닫아야 한다. 사용자 #6–9, #22, #23, #26, #31, #33.
4. **같은 동료와 기록에 여러 진입점이 있다.** 수비대, 몬스터 성장, 계약 동료, 출전·예비 편성, 합동기 편성, 동료 기억, 엔딩 도감, 연대기가 분리됐다. 접근성 설정도 일반 설정과 연대기의 ‘표시·조작 설정’에 나뉜다. 사용자 #4, #15, #16, #35, #36.
5. **한 화면에서 읽어야 할 상태가 너무 많다.** 후기 관리의 텍스트 블록은 건설 41/설정46, 수비대 37/37, 전술 38/39개다. 날짜 공지·적 예고·자원·지도 이름·탭 설명·선택 안내·하단 피드백이 같은 정보의 여러 표현을 제공한다. 버튼을 줄이는 것과 함께 정보의 공개 순서를 바꿔야 한다. 사용자 #5, #7, #11, #21, #33.

## 측정 정의와 읽는 법

- **텍스트 블록 실제/설정**: 화면에 걸치는 Label, RichTextLabel, Button/OptionButton의 비어 있지 않은 텍스트를 블록당 1개로 센다. 여러 줄은 1개다. ‘실제’는 Label의 보이는 줄 수가 1 이상, ‘설정’은 텍스트가 할당된 수다. 버튼의 텍스트와 버튼 안 별도 이름 라벨은 각각 센다. 픽셀 OCR로 글자 수를 센 값이 아니다.
- 글자 최소/최빈은 **실제 Control의 최종 font size**, 1920×1080 기준 px다. 동률은 모두 표기한다. 폰트의 보이는 잉크 높이는 이 값보다 작을 수 있다. 이미지에 그려 넣은 문자·직접 draw 문자열은 아래 별도 보충이다.
- 버튼은 일부가 보이는 BaseButton까지 포함하며 비활성 버튼도 센다. 빈 툴팁은 해당 버튼의 `tooltip_text`가 공백인 수다. ‘메뉴’, ‘취소’처럼 이름만으로 충분한 버튼도 포함하므로 **빈 툴팁 수=결함 수가 아니다**. 클릭하지 못한 것과 설명 공백도 다르다.
- `L/S/V`: 보이는 줄 0인 라벨 / ScrollContainer 경계 일부 잘림 / 화면 바깥 잘림 후보 수다. S는 스크롤의 정상 동작일 수 있다. 부모/자식 겹침, 모달이 배경을 덮는 것, 지도 표식의 의도된 겹침은 곧바로 버그로 판정하지 않았다. 실제 결함은 아래 D 표에 별도로 기록한다.
- 업데이트·메뉴·확인창·대화 로그는 가장 위 모달 안만 집계한다. 튜토리얼은 구멍이 있는 반투명 안내이므로 배경과 강조 대상을 포함한다. 따라서 화면 사이 수치는 동일 종류 안에서 비교하는 것이 적절하다.
- 초기 잘못 붙인 파일 이름은 보이는 실제 화면 기준으로 표의 이름을 정정했다. 예: `46_monster_day1`은 몬스터 화면이 아니라 **결과 확인 완료**다. 하네스/합성 상태 문제를 게임 문제로 셌다고 해석하면 안 된다.

## 핵심 루프 동선

‘클릭’은 눌렀다 놓는 1회다. UI 재구성·날짜 변화·대사 한 줄 교체를 모두 같은 ‘화면 전환’으로 세지 않았다. 화면 전환은 `current_screen` 종류 변경, 모달/탭/스크롤은 별도 이동이다. 아래는 탐색용 설정/로그/메뉴 왕복과 실패한 하네스 클릭을 제외해 **성공한 실제 동선의 핵심 단계만 재구성**한 수치다. 이번 DAY1은 실제로 배치 후 건설했으며 사용자가 적은 건설→배치 순서와 달랐다.

## UI 코드 구조와 교체 단위

### 현재 구조

`Main.tscn → GameRoot.tscn(Node2D) → CanvasLayer → HUDController/화면 빌더`다. 주요 씬은 배치 정보를 가진 완성된 UI 씬이 아니라 스크립트 연결 루트다. **Rect2를 사용한 Control 생성**이 중심이고 지도·상태표식은 직접 그린다. Rect2 자체는 단순 좌표 자료이므로 ‘모두 직접 그리기 UI’라고 분류하지 않는다.

- `GameRoot._set_screen()`(4203행)은 `hud.clear()` 후 화면을 재구성한다. 화면 선택·날짜·튜토리얼·콜백과 레이아웃이 일부 함께 존재한다.
- `HUDController.panel/child_panel/label/button/option_button/texture`가 공통 생성층이다. `ManagementWorkspaceUI`의 `panel/copy/button`을 여러 화면이 상속한다. 자동 배치 Container는 긴 목록/본문 안에 주로 사용한다.
- `UIUXTheme.gd`는 `.tres Theme`가 아니라 StyleBox를 반환하는 `RefCounted` 스타일 도우미다. `ObsidianStyleBox._draw()`는 테두리 그림을 나누어 그린다. 기존 `assets/ui/dark_fantasy/` StyleBoxTexture 경로와 함께 남아 있다. 전역 `.tres Theme`를 하나 바꿔 모든 화면이 교체되는 구조가 아니다.
- 본문/대사는 MapleStory Light, 강조/버튼은 Bold, 대체/CJK는 Noto CJK KR. 중국어는 Noto 경로를 선택한다. 숫자 피해는 Bold다. `UIFont.font_for_role()`로 중앙 정의하지만 별도 화면/전투 부품의 직접 font-size도 있다.
- 기준1920×1080, `canvas_items` 스케일. UISettings의 자동 compact 기준은 실제 창 너비1440 미만, 사용자 글자 배율0.9–1.15, 터치1.35배다. 일부 확장 화면은 자기 1920 디자인 캔버스를 다시 맞춘다. Chronicle은 가용 화면 크기로 계산하므로 방식이 일치하지 않는다.
- `HUDController._fit_label_to_bounds()`는 생성 후 글자를 줄이며 현재 하한9px다. `ManagementWorkspaceUI.copy()`는 `uiux_keep_font_size`를 설정해 한국어에서 크기 축소를 막는다. 이 예외와 고정 높이가 D01–03의 소실 문제를 만든다.
- `ReadableTooltipButton._make_custom_tooltip()`은 번역·22px 기준 배율·줄바꿈 높이를 처리한다. 설명 텍스트 연결 여부는 호출부마다 다르다.

## 개편 순서와 완료 조건 제안

1. **읽기/겹침 결함부터 해결**: 공통 라벨 높이·wrap·터치 배율, 마스크 무테, 컷신 HUD 레이어. 이름·비용·EXP가 실제로 보이고 탭/배속이 가려지지 않는 것이 완료 조건이다. 수정은 이번 감사에서 하지 않았다.
2. **정보 구조 결정**: 관리/성장/결과의 각 첫 화면에서 플레이어가 하는 결정을 하나씩 정의한다. 영구 성장·다음 전투 준비·정책·즉시 명령을 분리하고 중복 진입을 합친다.
3. **공통 컴포넌트**: 표면/텍스트/아이콘/상태바/툴팁/모달/스크롤의 크기·간격·행동 등급을 통일한다. Theme만 추가하고 고정 overrides를 남기는 접근은 피한다.
4. **사용자 시안 비교**: 중앙 타이틀, 좌우 대화, 관리+성장 또는 결과 연결 화면을 대표 시안으로 묶어 검토한다. 기존 이미지는 감사 참고이며 새 시안 제작/적용은 하지 않았다.
5. **화면별 교체**: 위 함수 단위를 순서대로 교체하고 관련 화면/동선만 검증한다. 전체 캠페인·다국어·21:9·기기 터치는 구현 범위가 정해진 뒤 별도 검증한다.

## 증거·검증·한계

- 실제 요청된 전수 화면 감사는 수행했다. 전체 회귀 테스트·전체 30일 플레이·밸런스·음악 청취·실제 Steam 실행·기기 터치 검증은 **NOT_REQUESTED/NOT_RUN**이다. 정식 출시 PASS가 아니다.
- 첫 프로세스의 tools 씬은 기본 저장이 차단돼 있었다. 감사 경로 연결 후 저장·타이틀 이어하기·별도 프로세스 복원이 정상이고, 이후 하네스 시작 시 감사 경로를 먼저 연결하도록 보완했다. 이는 제품 저장 코드를 수정한 것이 아니다.
- 후기 합성 상태에서 저장 요약/최종전 날짜가 실제 상태와 안 맞는 validator 경고가 있었다. 잘못된 기억ID 후보 74, 관리가 아닌 화면으로 리다이렉트된 106, 이름만 붙이고 의도한 화면에 도달하지 못한 14/16/19/22/29/32–35/50/53–55/57 등의 탐색 캡처를 실제 결함 재현으로 채택하지 않았다. 표에 남긴 중간 화면은 실제 내용으로 다시 이름 붙였고 제한을 적었다.
- 합성 상태의 저장 경고가 섞인 118/129–138은 제한된 상태/배치 확인용이다. 왕관/편성/컷신은 경고를 제거한 139–141로 대표를 다시 확인했다. 99의 지원 알림 겹침은 실제 스킬/보호 알림이다.
- 직접 그리는 동적 지도 글자·데미지 숫자와 반투명 레이어의 픽셀별 가림을 Control 값만으로 완전히 계수하지 못한다. 전체 OCR 기반 총라벨/최빈값으로 오해하지 않도록 정의와 별도 보충을 제공했다.
- 실행 로그의 가상 키보드 미지원/합성 상태 경고/종료 ObjectDB 잔여 경고는 별도 기록한다. script/parse 오류가 없는 것과 실행 경고가 없는 것은 다르다. 구현을 수정하지 않아 게임 결함은 남는다.
- [감사 도구 안내](../../../tools/ux_audit/README.md), 하네스 `Audit.gd/tscn`, 실행 `RunAudit.ps1`, 명령 `client.py`, 측정/축소 `measure.py`. 원본 PNG·라벨 JSON·측정 CSV/JSON·합성 세이브는 tmp에만 남는다. 대표 JPG12장만 저장소에 포함한다.

다음 작업자는 D01–03의 텍스트 소실과 관리/성장/결과의 정보 구조를 먼저 다뤄야 한다. ‘색·테두리를 바꾸면 전면 개편이 끝난다’는 범위는 이 감사 결과를 충족하지 못한다.
