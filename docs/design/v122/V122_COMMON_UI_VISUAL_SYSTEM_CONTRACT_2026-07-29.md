# v1.2.2 공통 UI 시각 체계 계약

기준일: 2026-07-29
적용 대상: Windows 출시판, 데스크톱 웹 테스트판
현재 적용 화면: 관리·배치, 환경설정, 공통 상단 상태 레일

## 1. Visual thesis

어둡고 장중한 성과 캐릭터가 먼저 보이고, 낡은 황동은 구조를 정리하며, 밝은 금색은 플레이어가 지금 결정할 단 하나의 행동에만 점등되는 전술 보드.

## 2. Content plan

1. 주 작업면: 성 지도·전장·현재 장면
2. 상시 지원: 자원·DAY·성 체력 같은 P0 상태
3. 문맥 정보: 선택한 방·전술·설정처럼 현재 결정에 필요한 P1
4. 세부 정보: 툴팁·드로어·접힘 영역의 P2/P3
5. 최종 행동: 화면마다 한 개의 주 행동

UI 프레임은 정보를 담기 위해 존재한다. 장식 자체를 보여주기 위한 빈 패널이나 중첩 카드는 만들지 않는다.

## 3. Interaction thesis

- hover는 80ms 밝기 상승으로 클릭 가능성을 알린다. 크기 변화로 레이아웃이나 hit rect를 흔들지 않는다.
- selected는 보라 면과 2px 외곽선으로 기존 실루엣을 유지한다.
- valid/success와 invalid/error는 각각 녹색·적색뿐 아니라 3px 외곽선 두께로도 구분한다.
- 드로어와 큰 화면 전환 모션은 접근성 motion gate가 연결되는 단계에서 추가한다.

### Gold budget

- 한 화면의 큰 `decision_gold` 주 행동은 최대 1개다.
- 금화 값처럼 의미가 고정된 작은 데이터 색은 허용하지만 외곽 프레임까지 금색으로 만들지 않는다.
- 정적 장식, 일반 버튼, 닫기, 되돌리기, 자원 plaque에는 밝은 금색을 쓰지 않는다.
- 현재 선택은 금색 대신 보라 면을 기본으로 하고, 튜토리얼의 실제 목표처럼 즉시 판단해야 하는 대상만 얇은 금색 focus를 허용한다.

## 5. 컴포넌트 등급

### Grade 1 — Primary

- 화면당 1개
- 예: `방어 시작`, 설정 `적용`, 침입 확인의 `배치 시작`
- 전체 고딕 프레임과 gold 계열 글자를 허용한다.
- 최소 높이 52px, 주변 행동보다 충분한 폭과 여백을 가진다.

### Grade 2 — Tactical

- 선택·전술·문맥 행동
- 예: 방 지침, 시설 후보, 전술 상세, 설정 category
- 어두운 보라 면, 얇은 금속/보라 외곽선, 장식 끝단 없음
- selected 상태에서도 같은 실루엣을 유지한다.

### Grade 3 — Utility

- 닫기·취소·되돌리기·보조 이동·상태성 컨트롤
- 무테 또는 1px divider 기반
- 배경은 투명에 가깝고 hover에서만 면을 드러낸다.
- primary보다 큰 프레임이나 밝은 gold를 사용할 수 없다.

### Danger

- 삭제·포기처럼 결과를 되돌리기 어려운 행동에만 사용한다.
- 적갈색 면과 굵은 외곽선으로 primary와 형태를 구분한다.

## 6. 공통 상태

| 상태 | 형태 | 색 | 문구/행동 |
|---|---|---|---|
| default | 1px 외곽선 | line/brass | 기본 |
| hover | 밝기 상승, 2px | 역할별 accent | hit rect 불변 |
| pressed | 짙은 면, 2px | 역할별 accent | 즉시 입력 피드백 |
| focus | 별도 2px ring | bright gold | 키보드/게임패드 포커스 |
| selected | 보라 면, 2px | route purple | 같은 컴포넌트 실루엣 유지 |
| valid target | 3px | success | 실제 logical target과 일치 |
| invalid target | 3px | danger | 상태 변경 없음, 이유 표시 |
| disabled | 낮은 대비, 1px | muted | 인접 문구/tooltip에 이유 |
| success | 3px | success | 실제 결과가 반영된 뒤 표시 |
| error | 3px | danger | 복구 행동 또는 다음 선택 제시 |

색을 제거해도 기본 1px, selected 2px, valid/error 3px의 두께 차이로 상태를 구분할 수 있어야 한다.

## 7. 상단 상태 레일

- 경제 자원은 독립된 장식 plaque 네 개가 아니라 하나의 연속 rail로 묶는다.
- 자원 그룹은 divider로만 구분하고 아이콘/이름보다 값이 먼저 읽히게 한다.
- DAY는 중앙 badge, 성 체력은 우측 bar로 분리한다.
- gold는 금화 값과 DAY 값에만 남기고 rail 외곽선은 낡은 brass/line으로 낮춘다.

## 8. 단계별 적용 규칙

- 공용 HUD에 등급·상태 함수를 먼저 추가한다.
- 기존 화면을 한꺼번에 기계적으로 바꾸지 않는다.
- 현재 단계에서는 관리·배치와 환경설정의 역할을 명시적으로 지정한다.
- 후속 화면은 해당 화면의 순차 단계에서 Primary 1개와 Tactical/Utility를 지정한다.
- 밸런스, AI, spawn, HP/ATK, 시설·몬스터 효과, 저장 의미는 변경하지 않는다.

## 9. 완료 기준

- 같은 역할의 버튼이 같은 공용 함수와 토큰을 사용한다.
- 관리·설정 화면에 큰 gold primary가 각각 1개 이하이다.
- 닫기·취소·되돌리기는 utility로 보인다.
- 선택된 설정 category와 몬스터 카드는 실루엣을 바꾸지 않고 selected 상태로 보인다.
- 상단 자원 UI가 조작 버튼이 아니라 상태 레일로 읽힌다.
- 기존 콜백·disabled reason·drag/drop·설정 적용/취소가 유지된다.
