# V1.2.2 도로·통로 리소스 수정 및 구현 브리핑

- 작성일: 2026-08-01
- 대상: Stage 01 관리·전투 지도
- 기준 브랜치: `codex/v122-ui-simplification`
- 목표: 바닥, 열린 방향, 외곽 벽을 하나의 격자 구조로 묶어 실제 던전 통로처럼 보이게 한다.

## 1. 무엇이 잘못되어 있었나

기존 도로는 주변 칸이 어디로 이어지는지 확인하지 않고 좌표의 홀수·짝수만 보고 네 장의 표면 그림을 반복했다. 따라서 직선, 모서리, 갈림길, 사거리의 모양이 구분되지 않았고 서로 붙어 있어도 낱개 발판처럼 보였다.

첫 교체안도 충분하지 않았다. 바닥에는 새 이미지를 썼지만, 벽은 각 칸 가장자리에 작은 이미지를 낮은 투명도로 따로 붙였고 방 벽은 코드 도형과 이미지 벽을 동시에 그렸다. 그 결과 통로를 감싸는 연속된 벽이 아니라 길 한가운데 놓인 울타리 조각처럼 보였다. 또한 DAY 3 연결로를 두 점 사이에 회전시킨 긴 바닥 이미지로 그려, 벽과 출입구 정보가 없는 도로 조각이 됐다.

도로 위 금색 선은 길 자체가 아니라 주요 이동 경로를 알려 주는 UI 안내선이다. 이 안내선이 너무 밝고 굵어 실제 도로보다 먼저 보이면서, 도로가 얇은 철사로 연결된 것처럼 보이는 문제도 있었다.

## 2. 리소스를 어떻게 다시 만들었나

### 도로 본체

- GPT 내부 이미지 생성으로 Stage 01의 보라빛 동굴과 맞는 넓은 현무암 판 재질을 만들었다.
- 원본은 `assets/source/imagegen/v122_stage01_spatial/road_autotile_v2/`에 보존했다.
- 게임용 결과는 `assets/tiles/stage_01/spatial_road_autotile_v2/corridor_road_autotile_stage01_atlas.png`다.
- 런타임 해상도는 한 칸당 128×64이며 전체 atlas는 2048×256이다.

여기서 atlas는 여러 타일 그림을 한 장에 모아 둔 이미지다. 한 도로 칸의 북·동·남·서 연결 여부를 네 개의 스위치처럼 읽으면 16가지 조합이 나온다. 각 조합에 재질 변형 네 가지를 넣어 총 64칸을 미리 구웠다.

| 연결 정보 | 값 | 화면에서 선택하는 모양 |
|---|---:|---|
| 북쪽 | 1 | 위 방향으로 열린 돌길 |
| 동쪽 | 2 | 오른쪽 방향으로 열린 돌길 |
| 남쪽 | 4 | 아래 방향으로 열린 돌길 |
| 서쪽 | 8 | 왼쪽 방향으로 열린 돌길 |

예를 들어 동쪽과 남쪽이 연결되면 값은 `2 + 4 = 6`이고, 런타임은 atlas의 6번 모서리 타일을 선택한다. 네 방향이 모두 연결되면 15번 사거리 타일을 사용한다.

### 일반 연결 통로

- 두 점 사이에 긴 이미지를 회전·확대하던 첫 교체안은 폐기했다.
- 모든 통로를 실제 격자 칸으로 만들고, 각 칸의 북·동·남·서 열린 방향을 바닥과 벽이 함께 사용한다.
- 열린 방향에는 벽을 만들지 않고, 닫힌 외곽에는 기존 Stage 01 석벽 bitmap을 충분한 크기와 불투명도로 겹쳐 배치한다.
- Stage 01에서는 코드로 만든 방 벽을 끄고 bitmap 석벽 한 종류만 사용해 이중 벽과 떠 있는 조각을 없앴다.

즉, 이제 통로는 “바닥 위에 벽을 장식처럼 얹는 그림”이 아니라 “걸을 수 있는 바닥과 그 바깥을 막는 벽”이라는 동일한 구조에서 만들어진다. 전투 이동 경로와 충돌 판정은 바꾸지 않았다.

### DAY 3 방어자 전용 지름길

- 지름길 중앙 결합부용 작은 현무암 교차판을 생성했다.
- 원본은 `assets/source/imagegen/v122_stage01_spatial/defender_connector_junction_v1/`에 보존했다.
- 게임용 결과는 `assets/tiles/stage_01/spatial_passage_v1/defender_connector_junction_stage01.png`다.
- 건설 후에는 `(18,12)`, `(19,12)`, `(18,13)`, `(19,13)` 네 칸을 실제 2×2 시각 격자에 추가한다.
- 네 칸 내부와 위·아래 출입구만 열고 좌우에는 연속된 석벽을 세워 짧은 던전 통로로 만든다.
- 건설 전에는 2×2 바닥을 만들지 않고, 위치를 알려 주는 작은 접속석만 표시한다.

이 표시만 바뀌며, 적이 지름길을 사용할 수 없고 우리 편 방어자만 사용할 수 있다는 전투 규칙은 기존 로직을 그대로 유지한다.

## 3. 코드에서는 어떻게 선택하나

```text
맵의 실제 연결 정보
  → 현재 칸의 북·동·남·서 연결을 0~15 값으로 계산
  → atlas에서 해당 모양과 재질 변형을 선택
  → 128×64 도로 칸으로 그리기

모든 통로 칸
  → 바닥이 이어진 방향을 열린 가장자리로 기록
  → 열린 가장자리에는 벽을 생략
  → 닫힌 외곽에만 연속된 bitmap 석벽 배치

DAY 3 지름길 상태
  → 미건설/건설 상태 확인
  → 건설 후에만 2×2 시각 격자와 위·아래 출입구 추가
  → 실제 적 이동 그래프에는 추가하지 않아 방어자 전용 규칙 유지
```

핵심 런타임 파일은 `scripts/dungeon_quarter/QuarterDungeonRenderer.gd`, 자산 연결표는 `data/dungeon_quarter/asset_manifest.json`이다. 원본 이미지를 게임이 직접 읽지 않고, 최적화된 런타임 이미지만 manifest를 통해 불러온다.

## 4. 이번에 같이 정리한 표시 우선순위

1. 연속된 석벽이 방과 통로의 바깥 경계를 먼저 설명해야 한다.
2. 석재 바닥과 열린 출입구가 실제 이동 방향을 보여 줘야 한다.
3. 방 입구 문턱과 통로 결합부가 바닥 위에서 자연스럽게 이어져야 한다.
4. 금색 주요 경로선은 길찾기 보조 UI로만 약하게 남아야 한다.
5. 선택 테두리·전투 효과·유닛은 그 위 계층에 표시한다.

금색 안내선은 폭 `1.5 → 1.0`, 중심점 반지름 `3.0 → 2.0`으로 줄이고 투명도를 낮췄다. 이제 도로를 가리는 본체가 아니라 필요할 때만 보이는 길찾기 보조선이다.

## 5. 검증 기준

- 16개 연결 모양과 네 가지 재질 변형의 중앙이 비어 있지 않아야 한다.
- 연결된 방향의 출구에는 불투명 픽셀이 있고, 연결되지 않은 방향에는 도로가 새어 나오지 않아야 한다.
- Stage 01 실제 맵의 모든 도로 칸이 0이 아닌 올바른 연결값을 가져야 한다.
- 시각적으로 열린 가장자리에는 벽 기록이 없어야 하고, 닫힌 외곽에는 벽이 정확히 하나 있어야 한다.
- 벽 bitmap의 표시 영역이 해당 벽의 양 끝점을 실제로 덮어 벽 사이에 틈이 없어야 한다.
- DAY 3 건설 전에는 연결부 네 칸이 없어야 하고, 건설 후에는 정확한 2×2 격자와 위·아래 출입구가 생겨야 한다.
- 실제 1280×720 관리 화면에서 석재 바닥과 외곽 벽이 같은 그림체와 해상도로 보여야 한다.
- 이동 경로, 적의 통로 사용 금지, 방어자 사용 허용, 건설 비용과 저장 상태는 기존 전투 테스트를 통과해야 한다.

## 6. 현재 결과와 다음 단계

도로 16방향 atlas와 연속 석벽, DAY 3의 실제 2×2 지름길 격자 연결을 완료했다. 회전한 도로 strip과 코드 도형 방 벽은 Stage 01에서 사용하지 않는다. 실제 Stage 01 DAY 3 관리 화면에서 건설 전·후를 각각 캡처했고, 열린 길 위 벽 금지·닫힌 외곽 벽 존재·벽 끝점 피복·적 이동 그래프 불변을 자동 테스트로 확인했다.

다음 단계에서는 방 입구 문턱과 도로의 접합부를 화면 전체에서 다시 확인하고, 서로 다른 시기에 만들어져 선명도·명암이 튀는 나머지 그래픽 요소를 같은 기준으로 정리한다. 전체 그래픽을 한꺼번에 흐리게 만드는 방식은 쓰지 않고, 문제가 있는 자산을 종류별로 교체한다.
