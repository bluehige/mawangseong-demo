# 마왕성 2.0 핵심 준비 UI 그래픽 양산 계획표

- 작성일: 2026-07-26
- 대상 버전: `2.0.0`
- 대상 화면: `건물 배치 → 몬스터 육성 → 수비대 배치`
- 기준 화면: `1280×720`
- 기본 원칙: 기존 마왕성 지도와 캐릭터 초상은 유지하고, 실제 게임 기능에 연결되는 그림만 만든다.

## 1. 결론

이번 UI를 위해 별도 장식 아이콘과 카드 배경을 대량 생성하지 않는다.

- 건물 카드 그림과 지도 설치 그림은 같은 runtime prop을 재사용한다.
- 선택 테두리, 설치 가능 위치의 빛, 효과 범위, 잠금과 경고는 Godot UI와 셰이더로 처리한다.
- 특화 선택은 `캐릭터 그림 + 역할 이름 + 추천 건물 그림`으로 설명한다. 역할마다 정체불명의 새 아이콘을 만들지 않는다.
- 현재 푸딩·곱·핀 초상은 그대로 사용한다.
- 새 캐릭터는 실제 전투 데이터가 확정될 때 한 명 단위로 추가한다. 빈 슬롯을 미리 그리지 않는다.

따라서 지금 필요한 고정 양산량은 시설 5종의 4방향, 총 20장이다. 생성 작업은 시설마다 4방향이 한 장에 들어간 원본 시트 5장으로 진행하고, 이를 runtime PNG 20장으로 분리한다.

## 2. 현재 자산 판정

| 대상 | 현재 UI 사용 자산 | 현재 판정 | 정식판 처리 |
|---|---|---|---|
| 마왕성 지도 | `assets/sprites/dungeon_gpt2/gpt2_dungeon_connected_map.png` | 재사용 가능 | 유지 |
| 푸딩·곱·핀 초상 | `assets/sprites/portraits/onboarding/portrait_*.png` | 재사용 가능 | 유지 |
| 바리케이드 | `prop_entrance_gate_v3_*` 임시 사용 | 전용 그림 없음 | 신규 제작 필수 |
| 병영 | `prop_weapon_rack_v3_*` | 기능 확인용 기존 자산 | V20 전용 정식 세트 제작 |
| 감시 초소 | `prop_watch_post_v3_*` | 기능 확인용 기존 자산 | V20 전용 정식 세트 제작 |
| 미끼 보물실 | `prop_treasure_pile_v3_*` | 기능 확인용 기존 자산 | V20 전용 정식 세트 제작 |

`data/dungeon_quarter/asset_manifest.json`은 현재 v3 방향별 이미지를 “키 선택과 기능 확인용이며 시각적으로 승인된 정식 자산은 아님”으로 기록한다. 따라서 기존 파일을 덮어쓰지 않고 `assets/props/v20/`에 정식 세트를 새로 둔다.

### 공통 제작 규격

| 항목 | 규격 |
|---|---|
| 생성 방식 | GPT 내부 이미지 생성 |
| 원본 시트 | 시설별 `1024×1024` PNG, 4방향 2×2 배열, 투명 배경용 단색 키 배경 또는 알파 후처리 |
| runtime | 투명 PNG, 기존 quarter-view 앵커와 크기 범위를 유지 |
| 투시 | 현재 마왕성의 quarter-view와 동일한 시점, 방향별 바닥 접점 고정 |
| 조명 | 어두운 동굴, 따뜻한 횃불과 보라색 마력광, 검은 영역 뭉개짐 금지 |
| 금지 | 글자, 숫자, 테두리, UI 카드 배경, 다른 시설과 합쳐진 장면, 외부 생성 서비스 |
| UI 축소 확인 | `48×48` 카드와 지도 위 약 `64~96px`에서 시설 종류가 구분되어야 함 |

## 4. 생성 원본과 출처 기록

시설별 폴더를 하나씩 만들고, 원본 시트와 runtime 4장을 한 `SOURCE.md`에 연결한다.

```text
assets/source/imagegen/v20_core_facilities/<facility_id>/
  SOURCE.md
  <facility_id>_four_facings_2026-07-26.png

assets/props/v20/
  prop_<facility_id>_v20_NW_<layer>.png
  prop_<facility_id>_v20_NE_<layer>.png
  prop_<facility_id>_v20_SE_<layer>.png
  prop_<facility_id>_v20_SW_<layer>.png
```

각 `SOURCE.md`에는 아래 고정 필드를 실제 존재하는 경로로 채운다.

```text
Generation model: GPT internal image generation
Generated date: YYYY-MM-DD
Target version: 2.0.0
Source image path: assets/source/imagegen/v20_core_facilities/...
Runtime image path: assets/props/v20/...
```

`Runtime image path`는 네 방향을 각각 한 번씩 기록한다. 후처리에는 배경 제거, 방향별 자르기, 바닥 접점 정렬, 크기 최적화를 기록한다.

## 5. 새 캐릭터 추가 때의 반복 생산 규칙

현재 화면은 캐릭터가 늘어나도 왼쪽 목록만 스크롤하고, 선택 상세는 한 명만 표시한다. UI 장식은 추가 생산하지 않는다.

| 실제 기능 추가 조건 | 캐릭터 한 명당 필요한 UI 이미지 | 수량 | 비고 |
|---|---|---:|---|
| 기본 몬스터가 실제 roster에 추가됨 | 관리·육성 공용 정사각 초상 | 1장 | `512×512`, 카드와 큰 상세에서 함께 재사용 |
| 특화 2종이 데이터에 추가됨 | 추가 이미지 없음 | 0장 | 역할명, 효과, 추천 시설 그림으로 표시 |
| 특화 후 외형이 실제로 바뀜 | 특화 초상 | 2장 | 외형 변화 기능이 확정된 경우에만 제작 |
| 전투 유닛이 새로 추가됨 | 기존 전투 스프라이트 계약에 따른 방향·행동 시트 | 별도 산정 | 준비 UI 양산과 섞지 않음 |
| 이야기 감정 표현이 필요함 | 감정 초상 | 별도 산정 | 스토리 화면 요구가 확정될 때만 제작 |

신규 캐릭터 runtime 경로 예시는 `assets/sprites/portraits/v20/portrait_<character_id>.png`, 원본 경로는 `assets/source/imagegen/v20_monsters/<character_id>/`로 고정한다.

## 6. 양산 순서와 승인 지점

| 순서 | 작업 | 사용자 확인 | 산출물 |
|---:|---|---|---|
| 1 | 바리케이드 4방향 기준 시트 제작 | 실루엣·재질·색 한 번 승인 | 원본 시트 1장 |
| 2 | 바리케이드 runtime 4장 분리 후 실제 UI 교체 | 1280×720 건물 카드와 지도에서 한 번 확인 | runtime 4장 |
| 3 | 승인된 기준으로 나머지 시설 4종을 한 묶음 생산 | 20장 비교표 한 번 확인 | 원본 시트 4장, runtime 16장 |
| 4 | 시설 ID 매핑을 `assets/props/v20/`로 교체 | 관련 배치 테스트와 대표 화면 1회 | 코드·자산 연결 |
| 5 | 이후 캐릭터 추가 시 한 명 단위 반복 | 캐릭터 기본 초상만 먼저 승인 | 캐릭터별 원본·runtime |

개별 이미지마다 별도 검수 작업을 만들지 않는다. 한 시설의 네 방향은 한 시트에서 확인하고, 전체 시설은 20장 비교표 한 번으로 확인한다. 잘못된 방향, 잘린 바닥 접점, 투명 배경 오류처럼 실제 사용을 막는 문제만 수정 대상으로 삼는다.

## 7. 이번 커밋 범위

- 현재 UI는 기능 확인을 위해 기존 v3 시설 그림을 임시 연결한다.
- 새 정식 이미지 20장은 이 계획 승인 뒤 별도 자산 작업으로 생산한다.
- 이번 커밋에는 생성 원본, 새 runtime 이미지, 로컬 캡처를 넣지 않는다.
- 시설 그림이 완성되면 코드의 시설 ID 매핑 경로만 `assets/props/v20/`로 교체한다.
