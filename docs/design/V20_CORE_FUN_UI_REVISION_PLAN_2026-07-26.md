- 문서 상태: 사용자 시안 승인·1차 구현 완료
- 작성일: 2026-07-26
- 대상: PC Web/Windows `1280×720`
- 작업 브랜치: `codex/v20-important-revision`
- 기준 SHA: `86cee02ab16b6afdab94af7d6152866de4eeed61`
- 예시 화면: `docs/design/V20_CORE_FUN_UI_MOCKUPS_2026-07-26.html`
- 기존 계획과의 관계: `V20_OFFICIAL_UI_REDESIGN_PLAN_2026-07-26.md`의 타이틀·침입 확인·전투·결과 방향은 유지하고, 준비 단계의 시설·편성·몬스터 배치 구조는 이 문서로 교체한다.

## 1. 이번 수정의 결론

게임의 준비 단계는 아래 두 가지 재미를 가장 먼저 보여줘야 한다.

1. 어떤 건물을 어느 구역에 놓을지 결정한다.
2. 몬스터를 어떤 역할로 키우고, 어느 건물 옆에 놓을지 결정한다.

이를 위해 별도의 복잡한 편성 검색 화면을 기본 흐름에서 제거하고, 같은 준비 과정 안에서 아래 세 단계만 사용한다.

```text
건물 배치 → 몬스터 육성 → 수비대 배치
```

상위 DAY 흐름은 기존 계약대로 유지한다.

```text
침입 확인 → 배치(위 세 단계) → 방어 시작 → 전투 → 결과
```

공식 게임명 `마왕님, 마왕성은 누가 지켜요?`, 기존 동굴 그래픽, 연결형 마왕성 지도, 푸딩·곱·핀과 현재 시설 5종은 바꾸지 않는다.

## 2. 실제 기능을 확인해 바로잡은 범위

### 현재 그대로 사용할 수 있는 것

- 시설 데이터 5종: 바리케이드, 병영, 감시 초소, 미끼 보물실, 회복 둥지
- 시설 비용과 고정 침입 경로
- 빈 시설칸 즉시 설치, 교체 확인, 한 단계 되돌리기
- 실제 성장 분기:
  - 푸딩: `성문 파수` / `구조 점액`
  - 곱: `도둑 사냥꾼` / `마무리 칼날`
  - 핀: `장거리 화염술` / `함정 화염술`
- `data/specializations.json`에 이미 정의된 역할별 추천 시설
- 기존 캠페인의 레벨, EXP, 유대, 훈련, 특화, 승급 저장 필드

### 구현과 함께 고친 제품 계약

현재 `V20_DAY1_5_VALIDATION_CONTRACT.md` 36행은 DAY 1~5에서 몬스터 성장을 사용하지 않는다고 고정한다. 반면 실제 역할 서비스와 성장 데이터는 존재하고, 이번 사용자 지시는 몬스터 육성을 건물 배치와 함께 핵심 재미로 확정했다.

따라서 이번 구현은 단순히 성장 화면만 붙이지 않고 아래 계약을 함께 고쳤다.

- DAY 1~5에서 한 번의 특화 선택을 허용한다.
- 특화 선택지는 `data/specializations.json`에서 읽고 UI에 가짜 분기를 하드코딩하지 않는다.
- 한 번에 선택한 캐릭터 한 명과 가능한 특화 두 갈래만 보여준다.
- 선택한 특화, 레벨, EXP와 유대를 V20 세션과 저장에 보존한다.
- 특화와 승급은 서로 다른 영구 선택으로 유지한다. 가짜 직선형 진화 트리로 합치지 않는다.
- 이미 특화를 확정한 캐릭터는 현재 역할과 추천 건물을 확인하고 바로 다음 단계로 넘길 수 있다.

일일 훈련 횟수·비용·해금 DAY는 아직 밸런스 계약이 없으므로 이번 구현에서 만들지 않았다. 시안의 `DAY 03`과 훈련 수치는 화면 구성을 보여주기 위한 예시였으며 실제 기능으로 연결하지 않았다.

## 3. 화면별 새 구조

| 단계 | 화면에서 가장 크게 보일 것 | 플레이어 행동 | 즉시 보여줄 결과 | 제거할 것 |
|---|---|---|---|---|
| 1. 건물 배치 | 기존 마왕성 지도와 설치된 건물 | 시설 카드 선택 후 빛나는 빈 칸 한 번 선택 | 지도 위 건물 미리보기, 적용 범위, `건설 7 → 3`, 설치 후 되돌리기 | 시설과 몬스터 동시 목록, 반복 설명, 모든 구역의 상시 강조 |
| 2. 몬스터 육성 | 선택한 실제 캐릭터의 큰 초상 | 실제 두 특화 분기 중 하나 선택 | 역할 변화, 추천 건물, 영구 선택 경고 | 가짜 캐릭터, 잠긴 빈 카드, 계약 없는 훈련, 특화·승급을 합친 가짜 성장 트리 |
| 3. 수비대 배치 | 건물이 남아 있는 같은 지도 | 몬스터 카드 선택 후 지도 한 번 선택 | 역할과 잘 맞는 건물 자리를 노란 테두리로 추천 | 현재 세 명을 위한 검색·필터·별도 편성 화면, 시설 목록 재표시 |

### 3.1 건물 배치

- 오른쪽에는 실제 시설 5종만 `그림 + 이름 + 핵심 효과 + 비용`으로 표시한다.
- 시설을 선택한 순간 놓을 수 있는 빈 시설칸만 보라색으로 밝힌다.
- 지도 위치를 가리키면 건물 그림, 작동 범위와 건설 점수 전후 값을 설치 전에 보여준다.
- 빈 칸 설치는 지도 한 번으로 끝낸다.
- 이미 건물이 있는 칸을 바꿀 때만 같은 패널 안에서 교체 확인을 받는다.
- 설치 직후 하단에는 결과 한 줄과 `되돌리기`만 남긴다.
- 고정 경로이므로 바리케이드가 길 자체를 바꾸는 것처럼 표시하지 않는다.
- 미끼 보물실은 현재 실제 동작에 맞춰 `도둑 지연`으로 표시하고, 연결되지 않은 목표 유인 기능은 약속하지 않는다.

### 3.2 몬스터 육성

- 왼쪽에는 보유 몬스터의 실제 초상, 이름, 레벨과 현재 성장 상태만 표시한다.
- 가운데는 선택한 캐릭터 한 명을 크게 보여주고 EXP·유대·현재 역할을 둔다.
- 오른쪽은 현재 가능한 선택 두 개만 비교한다.
- 성장 카드에는 긴 수치표 대신 `전투에서 하는 일`과 `추천 건물`을 그림으로 보여준다.
- 실제 특화 선택은 영구 적용 경고와 한 번의 확정 버튼을 사용한다.
- 승급이 열리는 시점에는 같은 영역을 승급 선택으로 교체하되 특화 기록은 그대로 남긴다.

### 3.3 수비대 배치

- 건물 배치 때 사용한 지도와 좌표를 그대로 유지한다.
- 지도에 설치된 건물 그림을 남겨 몬스터와의 관계를 직접 보게 한다.
- 오른쪽에는 이번 전투에 놓는 몬스터만 표시한다.
- 카드에는 `이름 + 현재 성장 역할 + 추천 건물 + 현재 위치`만 둔다.
- 카드를 선택한 뒤 지도 한 번으로 놓고, 목록과 지도 토큰을 즉시 같이 갱신한다.
- 추천 건물 근처는 노란 테두리와 한 줄 설명으로 안내한다.
- 추천 표시는 `data/specializations.json`의 `facility_synergy`를 읽어 만들며, 실제로 없는 추가 능력치 보너스를 꾸며내지 않는다.
- 마지막 배치 뒤에는 `되돌리기`와 `배치 완료`만 둔다.

## 4. 캐릭터와 건물이 늘어날 때의 구조

### 보유 몬스터 증가

| 상황 | 동작 |
|---|---|
| 현재처럼 전투 가능 몬스터 3명 | 별도 편성 화면 없이 세 명을 바로 표시 |
| 보유 수가 출전 한도보다 많음 | 준비 진입 때만 보유/출전 선택 서랍을 한 번 표시 |
| 성장 화면 | 왼쪽 목록만 세로 스크롤하고 선택 캐릭터 상세는 한 명만 렌더 |
| 출전 1~4명 | 배치 패널 한 열 |
| 출전 5~8명 | 초상과 역할을 줄인 두 열 카드 |
| 8명 초과 출전 | 현재 4구역×2슬롯의 실제 한도를 넘으므로 UI가 아니라 지도·전투 규칙부터 확장 |

새 캐릭터는 변경되지 않는 ID, 표시 이름, 초상, 전투 가능 여부, 역할 태그와 성장 선택 데이터만 등록하면 목록에 들어가게 한다. 없는 캐릭터 그림이나 잠긴 가짜 슬롯을 미리 채우지 않는다.

### 시설 증가

- 현재 시설 5종은 한 화면에 표시한다.
- 6종 이상이 되면 역할별 작은 탭과 세로 스크롤을 추가한다.
- 지도에는 설치된 시설과 지금 선택한 미리보기만 렌더한다.
- 시설 그림과 효과는 시설 ID로 연결해 이름 순서가 바뀌어도 잘못 매칭되지 않게 한다.

## 5. 실제 그래픽 자산 사용 원칙

시안은 아래 저장소 자산을 직접 사용했다.

- 지도: `assets/sprites/dungeon_gpt2/gpt2_dungeon_connected_map.png`
- 푸딩·곱·핀: `assets/sprites/portraits/onboarding/portrait_*.png`
- 병영·감시 초소·미끼 보물실·회복 둥지: `assets/props/v3/`의 실제 prop

현재 바리케이드 전용 prop은 없다. 기능 구현과 화면 확인에는 기존 `prop_entrance_gate_v3_SE_back.png`를 임시 사용했고, 나머지 네 시설도 기존 v3 prop을 시설 ID에 명시적으로 연결했다.

정식판에서는 기존 파일을 덮어쓰지 않고 `assets/props/v20/`에 시설 5종×4방향 20장을 새로 만든다. 상세 수량, 경로, 승인 순서와 출처 기록은 `V20_CORE_FUN_ART_PRODUCTION_PLAN_2026-07-26.md`를 따른다.

1. 양산 계획의 A0 바리케이드 4방향 기준 시트를 만든다.
