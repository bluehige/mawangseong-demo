# DAY 1~5 다음 구현 계획

최종 갱신: 2026-07-26

상세 과거 계획은 Git 이력에 보존한다. 이 문서는 지금부터 필요한 작업만 안내한다.

## 1. 완료된 기반

- PR 0: 제품 계약 고정
- PR 1: 단일 공간 모델
- PR 2: 다섯 상태 DAY 흐름
- PR 3: 배치와 실제 전투 인과 연결
- PR 4: DAY 1~5 적 구성과 밸런스 후보

이 단계의 대량 검수 결과를 UI만 바뀐 뒤 다시 반복하지 않는다.

## 2. 현재 작업 — 화면 단순화

구현 전 조건은 사용자의 시안 선택이다.

| 안 | 방향 |
|---|---|
| A | 기존 분위기를 유지하면서 글과 패널을 크게 줄임 |
| B | 지도와 아이콘 카드를 중심으로 바꿈 |
| C | 지도 비중을 가장 크게 하고 글을 거의 없앰 |

사용자가 A/B/C 또는 혼합 방향을 고르기 전에는 UI 코드·씬·런타임 자산을 수정하지 않는다.

선택 뒤에는 다음 순서로 진행한다.

1. 선택한 화면에서 꼭 필요한 행동과 정보만 남긴다.
2. 긴 설명은 한 줄 요약, 아이콘, 색과 배치로 대체한다.
3. 한 화면에서 동시에 보이는 버튼과 패널 수를 줄인다.
4. 변경과 직접 관련된 UI 테스트 1종을 실행한다.
5. `1280×720` 대표 화면을 한 번 확인한다.
6. 관련 문제가 없으면 핸드오프를 갱신하고 커밋한다.

## 3. 친구 테스트 빌드

화면 수정 뒤 사용자가 원하면 Web 테스트 빌드를 만든다.

- 권장 인원: 3~5명
- 권장 시간: 10~20분
- 질문: 막힌 곳, 불필요하거나 읽기 어려운 정보, 재배치 의향

친구 테스트에서 같은 문제가 두 번 이상 나오면 우선 수정 후보로 삼는다. 복잡한 점수표·영상 제출·이중 평가·고정 횟수 전투는 기본 절차가 아니다.

## 4. 검수 규칙

`docs/TESTING_POLICY.md`를 따른다.

- 문서 변경: `git diff --check`
- UI 변경: 관련 테스트 1종 + 대표 화면 1회
- 전투·데이터 변경: 관련 테스트 1종 + 바뀐 기능 자연 실행 1회
- 실패 시 실패한 항목과 영향 범위만 재실행

`RunCoreVerification` Quick/Full, 전체 플레이, 모든 플랫폼, 별도 검수 에이전트와 고정 대량 표본은 사용자가 명시적으로 요청한 별도 작업이나 공개 출시 후보에서만 실행한다.

## 5. 공개 출시

친구 테스트 빌드와 공개 출시본은 구분한다.

- 친구 테스트: 빠른 문제 발견용, `test/web-*` 또는 승인된 테스트 배포 사용
- 공개 출시: 최신 `main`에서 새 출시선을 만들고 별도 승인된 검수 수행

`release/v2.0` 실험선 전체를 `main`에 병합하거나 과거 커밋 묶음을 그대로 옮기지 않는다.

## 6. 중단 조건

다음 경우에만 작업을 멈추고 먼저 원인을 고친다.

- 게임이 시작되지 않음
- 변경한 화면에서 핵심 행동을 할 수 없음
- 저장이 손상됨
- 바뀐 기능의 관련 테스트가 실패함
- 기존 공개 태그·Release·빌드가 변경됨

그 외의 요청되지 않은 전체 검수 미실행은 중단 사유가 아니다.
