## 1. 먼저 바로잡는 것

### 폐기하는 이전 제안

- 메인 타이틀에 `2.0 친구 테스트`, `테스트 시작` 같은 별도 제품명을 붙이지 않는다.
- 공식 제목을 줄이거나 다른 이름으로 바꾸지 않는다.
- 없는 캐릭터, 가짜 캐릭터 이름과 가짜 시설을 시안에 넣지 않는다.
- 캐릭터 세 명을 기준으로 만든 고정 세로 목록을 최종 구조로 사용하지 않는다.
- 회색 작업 영역, 반복 카드, 개발자용 검증 문구를 정식 UI에 남기지 않는다.
- 현재 게임의 기능을 확인하지 않고 새 메뉴 흐름을 만들지 않는다.

### 반드시 그대로 유지할 제품 정체성

| 항목 | 정식판 고정값 |
|---|---|
| 공식 게임명 | `마왕님, 마왕성은 누가 지켜요?` |
| 현재 부제 | `F급 신입 마왕성 방어 튜토리얼` |
| 타이틀 배경 | `assets/ui/onboarding/scenes/scene_rookie_cave_start.png` |
| 기본 메뉴 | `새 게임`, `이어하기`, `빠른 시작`, `설정`, `엔딩 도감`, 데스크톱 `종료` |
| 저장 기능 | 저장 유효성 확인, 손상 저장 보호, 이어하기 DAY 표시 |
| 준비 지도 | `assets/sprites/dungeon_gpt2/gpt2_dungeon_connected_map.png` |
| 고정 경로 | `성문 전초 → 가시 회랑 → 중앙 전투실 → 왕좌 전실 → 왕좌` |
| 전투 화면 | 현재 `QuarterDungeonRenderer`, 전투 배경, 실제 monster/enemy sprite |
| 전투 조작 | `집결`, `집중`, `시설 발동`, `비상 후퇴`, `x1/x2/x3`, 일시정지 |
| 기본 캐릭터 | 푸딩, 곱, 핀 |
| 지원 캐릭터 예시 | 로로는 현재 데이터 계약대로 원정/정찰 지원 전용이며 전투 가능 상태로 꾸미지 않음 |
| 글꼴 | `NEXON_Maplestory_Light`, `NEXON_Maplestory_Bold` |

`V20TitleEntryPanel`에 있는 `2.0 PC 버티컬 슬라이스` 개발 패널은 정식판에서는 제거한다. 2.0이 정식 출시선이 되면 기존 `새 게임`과 `이어하기`가 그대로 2.0 흐름에 연결된다. 내부 개발 진입이 필요하면 공개 타이틀 UI가 아니라 개발 빌드 플래그 또는 디버그 실행 인자로만 유지한다.

## 2. 정식판 시각 방향

### 한 문장 기준

기존 동굴·보라 수정·금빛 횃불을 주인공으로 두고, UI는 얇은 금색 선과 짙은 자주색 면만 사용해 게임 그래픽을 가리지 않는 다크 판타지 작전판으로 만든다.

### 정보 우선순위

1. 타이틀에서는 게임 이름과 현재 선택 메뉴가 가장 먼저 보인다.
2. 준비에서는 마왕성 지도와 적의 이동 경로가 가장 먼저 보인다.
3. 배치에서는 선택한 시설 또는 캐릭터와 놓을 수 있는 위치만 강조한다.
4. 전투에서는 캐릭터·적·다음 위협이 가장 먼저 보인다.
5. 결과에서는 실패 원인 하나와 바로 고칠 행동 하나가 가장 먼저 보인다.

### 공통 표현 규칙

| 구분 | 정식 기준 |
|---|---|
| 바탕 | `#08070D` |
| 기본 패널 | `#100E16`, `#17131F` |
| 주 강조 | `#E8BB58`, `#FFE4A0` |
| 캐릭터/마법 강조 | `#9E7BD1` |
| 위험 | `#E56A72` |
| 성공 | `#58C997` |
| 본문 | `#F3EADC` |
| 작은 글자 | 실제 화면 기준 최소 12px |
| 본문 | 실제 화면 기준 14~16px |
| 버튼 | 실제 화면 기준 16~18px |
| 화면 제목 | 실제 화면 기준 22~40px |

- 큰 장식 프레임은 타이틀과 주 행동에만 쓴다.
- 목록 내부 카드는 평평한 면과 한 줄 테두리만 사용한다.
- 한 화면에서 금색으로 채운 주 버튼은 하나만 둔다.
- 같은 설명을 상단, 오른쪽, 하단에 반복하지 않는다.
- 지도와 전장은 불투명한 검정 패널로 덮지 않는다.
- 숫자는 `현재/최대`, 시간, 비용처럼 비교가 필요한 경우에만 항상 보인다.

## 3. 정식판 전체 흐름

```text
기존 공식 타이틀
  → 침입 확인
  → 시설 배치
  → 수비대 편성(필요한 경우에만)
  → 수비대 배치
  → 3초 방어 시작
  → 전투
  → 결과
```

현재처럼 보유 전투 캐릭터가 세 명이고 출전 한도도 세 명이면 `수비대 편성`은 자동 처리하고 화면을 건너뛴다. 캐릭터가 늘어 출전 인원을 골라야 할 때만 편성 서랍을 연다.

## 4. 화면 공통 좌표

준비 관련 화면은 같은 지도를 같은 위치에 유지해 화면 전환 때 시선이 흔들리지 않게 한다.

| 영역 | 1280×720 좌표 `(x, y, w, h)` | 역할 |
|---|---:|---|
| 상단 상태선 | `(0, 0, 1280, 68)` | DAY, 현재 단계, 건설, 명령력 |
| 지도/주 화면 | `(0, 68, 960, 541)` | 지도 또는 전장 |

## 6. 화면별 정식 구조

### 6.1 타이틀

- 공식 제목은 `마왕님, 마왕성은 누가 지켜요?`를 글자 하나도 바꾸지 않는다.
- 현재 동굴 배경의 왕좌와 보라 수정을 가리지 않도록 제목과 메뉴는 왼쪽 약 340px에 둔다.
- 메뉴 순서와 기능은 기존 것을 그대로 사용한다.
- 선택 메뉴 한 줄만 금색 면으로 강조하고 나머지는 얇은 구분선만 둔다.
- 하단에는 저장 상태와 실제 제품 버전만 작게 표시한다.
- 2.0 정식판에서 `새 게임`은 2.0 새 세션, `이어하기`는 유효한 2.0 저장으로 연결한다.

### 6.2 침입 확인

- 지도에는 1~4 구역, 왕좌, 붉은 침입선만 표시한다.
- 오른쪽에는 실제 적 sprite와 `적 이름 ×수`, 적의 최종 목표만 표시한다.
- 플레이어가 지금 결정해야 할 내용 한 줄을 하단 왼쪽에 둔다.
- 주 행동은 `배치 시작` 하나다.

### 6.3 시설 배치

- 오른쪽 탭은 `시설`만 활성화하고 수비대 목록은 숨긴다.
- 시설 카드는 실제 자산이 연결된 경우 `작은 그림 + 이름 + 한 단어 역할 + 비용`만 표시한다.
- 선택하면 놓을 수 있는 구역만 보라색으로 밝힌다.
- 새 설치는 즉시 반영하고 `되돌리기`를 유지한다.
- 기존 시설을 교체하는 경우에만 같은 오른쪽 패널 안에서 확인한다.

시안에 사용한 시설 그림은 저장소에 이미 있는 아래 자산을 정식 UI에 재사용할 수 있는지 보여주는 제안이다. 현재 V20 데이터에는 아직 연결돼 있지 않으므로 구현 때 ID별 연결과 게임 화면 크기에서의 식별성을 먼저 확인한다.

- `assets/props/v3/prop_entrance_gate_v3_SE_back.png`
- `assets/props/v3/prop_weapon_rack_v3_SE_back.png`
- `assets/props/v3/prop_watch_post_v3_SE_front.png`
- `assets/props/v3/prop_treasure_pile_v3_SE_front.png`
- `assets/props/v3/prop_recovery_nest_v3_SE_front.png`

### 6.4 수비대 편성

편성은 보유 캐릭터가 늘어날 때만 필요한 선택이다. 준비 지도의 오른쪽에 계속 쌓지 않고, 지도 위에 큰 서랍을 열어 한 번에 결정한다.

| 영역 | 좌표 `(x, y, w, h)` | 내용 |
|---|---:|---|
| 편성 서랍 | `(54, 38, 1172, 644)` | 전체 편성 화면 |
| 보유 목록 | `(54, 38, 782, 644)` | 검색, 역할 필터, 3열 카드 |
| 출전 명단 | `(836, 38, 390, 644)` | 출전 순서와 한도 |
| 보유 카드 | 약 `(232×142)` | 초상, 이름, 역할, 선택 번호 |
| 한 화면 표시량 | `3열 × 3행 = 9명` | 이후 목록만 스크롤 |

- 현재 보유 전투 캐릭터가 출전 한도 이하이면 전원을 자동 편성하고 서랍을 열지 않는다.
- 출전 인원을 골라야 할 때만 준비 과정에서 한 번 자동으로 연다.
- 배치 화면의 `편성 N/M`을 눌러 언제든 다시 열 수 있다.
- 카드에는 초상, 이름, 한 단어 역할, 출전 번호만 둔다.
- 체력·공격력·스킬 설명은 카드에 반복하지 않고 선택한 캐릭터 상세에만 보여준다.
- 전투 배치가 금지된 로로 같은 캐릭터는 `정찰 지원` 상태를 명확히 표시하고 출전 번호를 부여하지 않는다.

### 6.5 수비대 배치

- 오른쪽에는 출전 명단만 표시한다.
- 지도에 배치된 캐릭터는 실제 초상을 작은 원형 토큰으로 표시한다.
- 선택한 캐릭터와 배치 가능한 빈 슬롯만 보라색으로 강조한다.
- 지도 토큰은 캐릭터당 하나만 표시하고, 목록과 지도 사이의 배치 상태를 같은 ID로 관리한다.
- 하단에는 선택된 캐릭터와 가능한 조작 한 줄, `되돌리기`, `배치 완료`만 둔다.

### 6.6 방어 시작

- 마지막 배치 지도를 그대로 둔다.
- 오른쪽 중앙에 큰 숫자만 표시한다.
- 카운트다운 중 변경하려면 `배치로 돌아가기` 하나만 제공한다.
- 전투 직전 상태 저장은 그대로 수행하지만 내부 저장 용어는 보여주지 않는다.

### 6.7 전투

- 전투 배경은 연결형 준비 지도로 교체하지 않는다.
- 기존 전투 렌더러 위에 얇은 HUD만 올린다.
- 왕좌 HP는 왼쪽 위, 현재 DAY·구역은 가운데 위, 속도와 정지는 오른쪽 위에 둔다.
- 다음 위협 카드는 오른쪽 위 하나만 표시한다.
- 명령 버튼은 화면 아래에 이름과 비용만 표시한다.
- 명령을 선택한 뒤에만 `공병을 고르세요`처럼 다음 조작을 한 줄로 표시한다.
- 캐릭터와 적의 실제 sprite보다 큰 UI 장식은 사용하지 않는다.

### 6.8 결과

- 방금 전투한 동굴 배경을 어둡게 유지해 화면이 별도 관리 도구처럼 보이지 않게 한다.
- 왼쪽에는 승패, 피해, 무너진 곳, 다음 수정, 지표 두 개를 둔다.
- 오른쪽에는 실제 캐릭터 초상과 대표 기여 하나를 둔다.
- 실패 시 `같은 배치 재도전`, `배치 수정`을 유지한다.
- 승리 시 주 행동을 `다음 침입`으로 바꾼다.

## 7. 캐릭터가 계속 추가돼도 버티는 구조

### 데이터 구조

현재 `placement_state.roster` 하나가 보유, 출전, 배치를 모두 겸하는 방식은 다음 세 단계로 분리한다.

```text
owned_defender_ids
  └─ 플레이어가 보유한 모든 캐릭터 ID

active_defender_ids
  └─ 이번 전투에 출전하는 캐릭터 ID와 순서

placement_state.roster[id]
  └─ 출전 캐릭터의 room_id, slot_id, 현재 배치 상태
```

- 캐릭터는 표시 이름이 아니라 변경되지 않는 `character_id` 또는 `monster_instance_id`로 저장한다.
- 출전 한도는 코드에 `3`으로 고정하지 않고 DAY·모드 설정값으로 받는다.
- 현재 지도는 `4구역 × 2슬롯`이므로 동시에 실제 배치 가능한 상한은 8명이다.
- 8명을 넘겨 출전시키려면 UI만 늘리는 것이 아니라 지도 슬롯, 전투 공간, 밸런스 규칙을 함께 변경해야 한다.
- 보유 캐릭터 수는 30명 이상이어도 목록만 늘어나도록 제한하지 않는다.

### 보유 수에 따른 동작

| 보유/출전 상황 | 동작 |
|---|---|
| 보유 전투 캐릭터 1~3명, 한도 3명 | 전원 자동 편성, 편성 화면 생략 |
| 보유 4명 이상, 한도 3명 | 편성 서랍 자동 표시 |
| 출전 1~4명 | 오른쪽 명단 한 열 |
| 출전 5~8명 | 오른쪽 명단 두 열의 작은 카드 |
| 보유 10~30명 이상 | 9장만 렌더하고 스크롤에 따라 보이는 카드만 갱신 |

### 새 캐릭터 추가 규칙

- 새 캐릭터는 ID, 표시 이름, 역할 태그, 전투 가능 여부, 초상 경로만 등록하면 목록에 자동으로 들어온다.
- 초상이 아직 없으면 임의 캐릭터 그림을 대신 쓰지 않고 동일한 `준비 중` 실루엣을 표시한다.
- `전열`, `추격`, `원거리`, `지원` 등 역할 필터는 데이터 태그에서 생성한다.
- 이름 검색, 역할 필터, 스크롤 위치와 선택 상태는 편성 화면을 닫았다 열어도 유지한다.
- 키보드는 화살표로 카드 이동, Enter로 출전 전환, Page Up/Down으로 한 화면 이동을 지원한다.
- 컨트롤러는 방향키 이동과 확인/취소가 같은 규칙을 사용한다.

### 기존 저장 호환

- 이전 저장에 `active_defender_ids`가 없으면 현재 roster의 전투 가능 캐릭터를 기존 순서대로 출전 명단에 넣는다.
- 출전 한도를 넘는 이전 데이터가 있으면 자동 삭제하지 않고 편성 화면을 열어 사용자가 결정하게 한다.
- 지원 전용 캐릭터는 보유 목록에는 남기되 배치 데이터로 변환하지 않는다.
- 기존 사용자 데이터 폴더명은 저장 호환 때문에 변경하지 않는다.

## 10. 꼭 필요한 확인만 실행

사용자가 전체 검수를 별도로 요청하지 않는 한 아래만 확인한다.

1. 공식 타이틀 메뉴의 기존 callback과 저장 유효성 확인
2. 준비 화면 관련 UI 테스트 1종
3. 편성 데이터의 `3명`, `9명`, `30명`, 이전 저장 변환 단위 테스트
4. `1280×720`에서 타이틀 → 침입 → 시설 → 편성 → 배치 → 전투 → 결과 대표 흐름 1회
5. 전투 명령 하나의 선택과 대상 클릭 1회
6. `git diff --check`

기본으로 생략한다.

- 전체 Quick/Full 회귀
- 모든 DAY와 모든 seed
- 모든 해상도와 모든 플랫폼
- 전체 플레이
- 별도 검수 에이전트
- Web/Windows 동시 빌드

## 11. 승인 기준

구현에 들어가기 전 다음 다섯 가지를 이 문서와 예시 화면으로 확정한다.

1. 공식 제목과 기존 메뉴는 그대로 두고 개발용 2.0 패널만 제거한다.
2. 준비 화면은 `지도 75% + 오른쪽 현재 작업 + 하단 행동 하나`로 통일한다.
3. 현재 3명은 자동 편성하고, 캐릭터 증가 시에만 큰 편성 서랍을 연다.
4. 현재 지도의 실제 동시 출전 상한은 8명으로 두고 보유 목록은 제한 없이 확장한다.
5. 기존 그래픽을 우선 재사용하고, 새 런타임 그래픽은 별도 사용자 승인 뒤 제작한다.
