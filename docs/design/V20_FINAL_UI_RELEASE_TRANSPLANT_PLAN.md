## 2. 이번 사용자 결정이 기존 문서보다 우선하는 항목

기존 PR 5 수용 계획에는 v2.0 검증 도중 `RunCoreVerification.ps1 -Mode Full`, 실제 물리 70전, QA 24전, 초회 사용자 10명 테스트가 포함되어 있다. 이번 작업부터 아래 정책으로 변경한다.

1. UI 개발 중에는 전체 회귀·전체 플레이·별도 검수 에이전트를 실행하지 않는다.
2. UI PR마다 직접 관련된 테스트와 해당 화면의 실제 렌더만 확인한다.
3. v2.0 UI 후보는 사용자가 직접 플레이해 승인한다.
4. 사용자 승인 전에는 정식 출시 계보에 코드를 옮기지 않는다.
5. 승인 후 정식 출시 브랜치에 선별 이식한다.
6. 모든 출시 기능이 정식 출시 브랜치에 모인 뒤 RC SHA를 동결한다.
7. **동결된 RC SHA에서만 전체 검수를 수행한다.**
8. 전체 검수 PASS 뒤 런타임 파일을 변경하지 않고 즉시 최종 빌드를 만든다.
9. 전체 검수 뒤 코드·데이터·씬·자산이 한 파일이라도 변경되면 기존 PASS는 무효이며, 새 RC SHA에서 전체 검수를 다시 수행한다.

이 정책을 코드 수정 전에 문서 PR로 먼저 고정한다.

## 3. 제품 UI 목표

### 3.1 최상위 목표

1. 화면마다 플레이어가 해야 할 행동은 한 가지가 가장 크게 보여야 한다.
2. 맵과 전장이 화면의 중심이어야 하며, UI가 게임 공간을 가리지 않아야 한다.
3. 상시 정보, 상황 정보, 선택 정보가 섞이지 않아야 한다.
4. 시설·몬스터 배치는 설명을 읽지 않고도 드래그와 클릭으로 수행할 수 있어야 한다.
5. 전투 중 명령의 대상, 적용 여부, 지속 상태가 실제 전장과 연결되어 보여야 한다.
6. 결과 화면은 통계보다 “왜 이겼거나 졌는지”와 “다음에 무엇을 바꿀지”를 먼저 보여야 한다.

### 3.2 정보 노출 규칙

| 정보 등급 | 항상 표시 | 조건부 표시 | 선택했을 때만 표시 |
|---|---|---|---|
| 진행 | DAY, 현재 단계, 주 행동 버튼 | 카운트다운, 진행 차단 사유 | 상세 규칙 |
| 준비 | 건설 자원, 배치 완료 여부, 고정 침입 순서 | 유효 슬롯, 비용 부족, 교체 확인 | 방·시설·몬스터 상세 |
| 전투 | 왕좌 HP, 현재 방어 구역, 명령력, 속도 | 적 특수행동 예고, 명령 대상 지정, 명령 적용 중 | 유닛·시설 상세 |
| 결과 | 승패, 핵심 원인, 다음 행동 | 주요 기여 2~3개 | 상세 전투 장부 |

### 3.3 최소 가독성 기준

1280×720 기준:

- 핵심 제목: 20px 이상
- 주요 값·주 행동: 18px 이상
- 버튼 글자: 15px 이상
- 일반 본문: 13px 이상
- 보조 문구: 11px 이상
- 주요 클릭 영역 높이: 40px 이상
- 움직이는 전장 위 텍스트는 불투명도 높은 배경 패널을 사용
- 색만으로 성공·실패·선택 상태를 구분하지 않고 아이콘·문구·테두리를 함께 사용
- 주요 조작은 마우스와 키보드 포커스 모두 가능해야 함

- 유효 저장이 있을 때만 보조 행동 `이어하기`
- 디버그 빌드에서만 화면 모서리에 source SHA와 build flavor 표시

- `2.0 PC 버티컬 슬라이스` 개발자용 문구
- 선택지가 하나뿐인 난이도 선택 버튼

- 주 행동 버튼은 화면에 하나
- 저장이 없으면 이어하기 영역은 숨김 또는 명확한 비활성 사유 표시
- v1.2.1 저장과 분리된다는 안내는 작은 보조 문구로 유지

## 4.2 침입 확인

현재의 단순 텍스트 화면을 “이번 전투에서 무엇이 오는지 확인하는 한 장의 브리핑”으로 수정한다.

### 항상 표시

- DAY
- 적 편대 대표 아이콘과 이름
- 적의 목표
- 고정 침입 순서
- 이번 DAY에서 새롭게 주의할 행동 1개
- 주 행동 `배치 시작`

### 금지

- 탭
- 상세 설정
- 아직 사용할 수 없는 전술 명령 버튼
- 긴 설명문
- 같은 정보를 상단·중앙·하단에 중복 표시

### 합격 기준

- 사용자가 적의 목표와 다음 행동을 한 화면에서 확인
- `배치 시작` 외에 경쟁하는 주 행동 없음
- 브리핑을 닫거나 넘기는 추가 버튼 없음

## 4.3 시설·몬스터 배치 화면

### 화면 구조

- 상단: DAY, 남은 건설 자원, 적 의도 요약, 배치 상태
- 중앙 70~75%: 마왕성 맵과 고정 침입로
- 우측 25~30%: `시설` / `몬스터` 두 도구
- 하단: 배치 유효 여부, 되돌리기, 주 행동 `방어 시작`

맵은 방이나 슬롯을 선택해도 크기와 위치가 변하지 않아야 한다.

### 시설 도구

시설 카드에 아래 정보만 표시한다.

- 이름
- 비용
- 핵심 효과 한 줄
- 드래그 표시

시설을 선택하거나 끌기 시작하면:

- 설치 가능한 시설 슬롯만 금색 강조
- 설치 불가능한 슬롯은 어둡게 처리
- 비용 부족·점유·잘못된 슬롯의 이유를 짧게 표시
- 기존 시설 위에 놓으면 교체 확인을 한 번만 표시
- 설치 완료 뒤 자원 변화와 효과를 짧은 토스트로 표시

### 몬스터 도구

몬스터 카드에 아래 정보만 표시한다.

- 초상화
- 이름
- 역할 한 단어
- 현재 배치 구역
- 드래그 표시

드래그 중에는:

- 유효 몬스터 슬롯만 보라색 강조
- 슬롯 2개가 찬 구역은 비활성화하고 `2/2` 표시
- 배치 완료 시 맵 토큰과 카드의 현재 위치가 동시에 갱신
- 역할 상세와 성장 상세는 카드를 선택했을 때만 표시

### 방·슬롯 선택

- 방 상세는 별도 대형 inspector로 열지 않는다.
- 우측 도구함의 하단 요약 영역에서 선택한 방의 시설·몬스터·효과를 보여준다.
- 맵 위에는 시설 슬롯 1개와 몬스터 슬롯 2개의 상태가 직접 보이게 한다.
- 배치된 토큰을 선택하면 `이동`, `제거`, `교체` 중 가능한 행동만 표시한다.

### 하단 행동 영역

- `되돌리기`는 보조 행동으로 고정
- 배치가 유효하지 않으면 `방어 시작`을 비활성화하고 이유를 같은 영역에 표시
- 유효하면 `방어 시작`만 주 행동으로 강조
- 시설 비용 상한, 몬스터 미배치, 중복 슬롯 같은 내부 규칙을 개발자 문구로 노출하지 말고 사용자 문장으로 변환

### 합격 기준

- 시설 설치: 드래그 1회 또는 카드 클릭→슬롯 클릭
- 몬스터 배치: 초상 드래그 1회 또는 카드 클릭→슬롯 클릭
- 잘못된 배치 시 상태가 변경되지 않고 이유가 표시됨
- 설치·교체·이동·제거·되돌리기가 모두 시각적으로 확인됨
- 지도는 선택 전후 동일 크기
- 상시 방 inspector, 위협 rail, 단계 ribbon, 로그, 방 목록 패널 없음
- 1280×720에서 카드명·비용·효과가 잘리지 않음

## 4.4 방어 시작 카운트다운

- 중앙에 3초 카운트다운
- `배치가 저장되었습니다` 한 줄
- 보조 행동 `배치로 돌아가기`
- 다른 설정과 정보는 숨김
- 0이 되면 추가 확인창 없이 전투 진입

합격 기준:

- 카운트다운 중 실수로 전장이나 뒤쪽 UI가 클릭되지 않음
- 취소 시 방금 확정한 배치가 그대로 복원됨
- 이 화면에서 주·보조 행동 외 버튼 없음

## 4.5 전투 HUD

### 화면 구조

- 중앙 전장은 가장 넓은 영역을 유지
- 전장을 덮는 검은 패널 금지
- 상단 왼쪽: DAY, 전투 목표, 왕좌 HP
- 상단 오른쪽: x1/x2/x3/일시정지의 작은 분할 컨트롤
- 맵 또는 상단 얇은 영역: 1~4차 방어 구역 진행 상태
- 상단 중앙: 실제 위협이 있을 때만 나타나는 경고
- 하단: 전술 명령 4개를 한 줄의 압축 버튼으로 표시

### 방어 단계

- `성문 전초 → 가시 회랑 → 중앙 전투실 → 왕좌 전실`을 한 줄로 표시
- 현재 구역 강조
- 돌파된 구역, 교전 중인 구역, 대기 구역을 텍스트와 상태 아이콘으로 구분
- 같은 정보를 좌측 대형 표와 맵에 중복 표시하지 않음

### 적 위협 예고

- 실제 예고가 없으면 패널 자체를 숨김
- 예고가 생기면:
  - 적 행동
  - 남은 시간
  - 권장 명령
  - 권장 대상
  만 표시
- 예고 종료 즉시 사라짐
- `예고 없음` 패널을 상시 표시하지 않음

### 전술 명령

기능 4종은 유지하되 현재의 큰 다중 문장 버튼을 압축한다.

- 집결
- 집중
- 시설 발동
- 비상 후퇴

버튼 기본 표시:

- 아이콘 또는 짧은 표식
- 명령명
- 비용
- 사용 가능/재사용 대기 상태

명령을 선택했을 때만:

- 대상 종류
- 예상 효과
- 취소 방법
- 유효 대상 강조

명령 적용 후:

- 실제 적용 대상
- 남은 지속시간 또는 완료 상태
- 명령력 차감
- 성공·실패 이유

를 화면에서 확인할 수 있어야 한다.

### 선택 정보

- 명령을 선택하지 않았을 때 `선택 대상: 전장에서 선택` 같은 빈 정보를 상시 표시하지 않음
- 유닛·시설 세부 정보는 클릭 시 작은 컨텍스트 패널로만 표시
- 전투 로그와 전체 유닛 목록은 상시 노출하지 않음

### 합격 기준

- 전장, 유닛, 공격, 경로, 경고를 UI가 가리지 않음
- 위협이 없을 때 경고 패널 없음
- 명령 선택 전 대상 안내 없음
- 명령 선택 후 유효 대상만 강조
- 명령 성공 후 적용 상태가 즉시 보임
- 명령 실패 시 이유가 표시되고 명령력이 차감되지 않음
- x1/x2/x3/정지 컨트롤은 전술 명령보다 시각적 우선순위가 낮음
- 1280×720에서 네 명령을 읽을 수 있으나 전장보다 크게 보이지 않음

## 4.6 결과·재도전 화면

- 잘한 점 1개

승리:

- 주 행동 `다음 침입 확인`

패배:

- 주 행동 `배치 수정`
- 보조 행동 `같은 배치 재도전`

게임의 핵심이 배치 학습이므로 패배 화면에서는 같은 배치 재도전보다 배치 수정을 우선한다.

상세 정보는 접기/펼치기 또는 하단 보조 영역으로 둔다.

### 합격 기준

- 화면을 보자마자 패배 원인과 다음 행동을 이해
- 패배 시 배치 수정이 가장 큰 버튼

## 10. U5 사용자 테스트 후보 패키지

U5는 기능을 추가하지 않는다. U1~U4가 병합된 정확한 SHA를 고정하고 다음을 제공한다.

### 필수 산출물

- source full SHA
- branch
- Reviewed SHA
- Windows debug ZIP
- Windows ZIP·EXE·PCK SHA-256
- Web debug PCK·WASM SHA-256
- 1280×720 관리 화면
- 1280×720 전투 화면
- 1280×720 결과 화면
- 1366×768 관리·전투 화면
- 수정 전/후 핵심 차이 표
- 알려진 제한 사항
- 사용자 테스트 순서

### 사용자 테스트 순서

1. 새 테스트 시작
2. 침입 목표 확인
3. 시설 1개 설치
4. 몬스터 3종 배치 또는 이동
5. 잘못된 슬롯에 한 번 drop
6. Undo 한 번
7. 방어 시작
8. 전투에서 적 예고 확인
9. 명령 1회 사용
10. 승리 또는 패배 결과 확인
11. 패배 시 배치 수정
12. DAY 진행 또는 재도전

### 사용자 판정 질문

- 첫 행동을 바로 알 수 있었는가
- 시설과 몬스터를 어디에 놓아야 하는지 알 수 있었는가
- 중요한 정보가 너무 작거나 가려지지 않았는가
- 전투 중 적의 행동과 명령 대상을 알 수 있었는가
- 패배 원인과 다음 수정 행동을 알 수 있었는가
- 불필요하거나 의미를 알 수 없는 버튼이 남아 있는가
- 이 UI를 정식판 기준으로 사용해도 되는가

### 승인 기록

사용자의 명시적 승인 문구가 있어야 한다.

```text
V20_UI_OWNER_ACCEPTED
source_sha: <full SHA>
build_hash: <Windows ZIP SHA-256 또는 Web PCK SHA-256>
decision: 정식 출시본 이식 승인
```

Codex가 targeted test 통과만으로 이 상태를 기록하면 안 된다.

새 기능·데이터·자산 수정으로 SHA가 바뀌면 이전 승인은 무효다.
