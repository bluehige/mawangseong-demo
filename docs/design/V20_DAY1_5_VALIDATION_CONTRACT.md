# 마왕성 DAY 1~5 핵심 제품 계약

최종 갱신: 2026-07-26

이 문서는 `release/v2.0` 실험선의 행동 기준만 간단히 고정한다. 검수 방법은 `docs/TESTING_POLICY.md`가 우선한다. 2026-07-23까지의 대량 검수 계획과 수치 탐색 기록은 Git 이력과 `docs/handoff/V20_ACCEPTANCE_TOOLING_CONTRACT_AMENDMENT_2026-07-23.md`에 보존하지만 앞으로의 일상 작업 기준으로 사용하지 않는다.

## 1. 현재 상태

- PR 0~4의 DAY 1~5 공간·진행·배치 인과·밸런스 후보 구현은 완료되어 있다.
- `release/v2.0`은 실험선이며 `main`이나 공개 출시선이 아니다.
- UI는 사용자가 A/B/C 예시 중 방향을 고르기 전까지 수정하지 않는다.
- 70전·24전·10명 고정 검수는 폐기된 기본 계획이다. 공개 출시 후보에서 필요하면 사용자와 새 범위를 합의한다.

## 2. 하루 진행

하루는 아래 다섯 상태만 사용한다.

```text
침입 확인 → 배치 → 방어 시작 → 전투 → 결과
```

| 상태 | 핵심 행동 |
|---|---|
| 침입 확인 | 적과 목표를 보고 `배치 시작` |
| 배치 | 시설과 몬스터를 놓고 `방어 시작` |
| 방어 시작 | 배치를 저장하고 3초 뒤 전투 시작, 취소하면 배치로 복귀 |
| 전투 | 집결·적 집중·시설 발동·비상 후퇴와 속도·일시정지 사용 |
| 결과 | 승패와 실제 기여를 보고 다음 DAY 또는 재도전 선택 |

결과를 건너뛰어 다음 DAY로 가거나 배치 없이 전투를 시작할 수 없다. DAY 5 승리 결과는 종료 상태다.

## 3. 자원과 재도전

- 보통 난이도의 시설 설치 총비용 상한은 10, 명령력은 3이다.
- 슬라임·고블린·임프는 각각 한 슬롯을 사용한다.
- DAY 1~5에서는 몬스터 성장과 반복 패배 보상을 사용하지 않는다.
- 새 DAY는 이전 배치를 유지하되 상한 10 안에서 수정한다.
- `배치 수정`과 `같은 배치 재도전`은 같은 전투 직전 상태를 복구한다.
- 재도전으로 HP, 명령력, 시설 충전, 건설 점수나 난수를 유리하게 누적할 수 없다.

## 4. 단일 공간 모델

침입 순서는 하나로 고정한다.

```text
성문 전초 → 가시 회랑 → 중앙 전투실 → 왕좌 전실 → 왕좌
```

| 순서 | `zone_id` | 표시 이름 |
|---:|---|---|
| 1 | `gate_outpost` | 성문 전초 |
| 2 | `spike_corridor` | 가시 회랑 |
| 3 | `central_battle_room` | 중앙 전투실 |
| 4 | `throne_anteroom` | 왕좌 전실 |
| 5 | `throne` | 왕좌 |

준비 화면의 슬롯, 저장 데이터, 전투 생성 위치, 명령 대상, 시설 효과와 결과 화면은 모두 같은 `data/v20/dungeon_layouts.json` 좌표와 `zone_id`를 사용한다. 준비 화면만 바뀌고 실제 전투 위치가 바뀌지 않는 구현은 허용하지 않는다.

## 5. 배치가 실제 결과를 바꾸는 규칙

- 몬스터는 저장된 슬롯 위치에서 생성되고 자기 구역의 적을 우선한다.
- 시설 효과는 실제 유닛이 시설 전투 범위 안에 있을 때만 적용한다.
- 집결과 비상 후퇴만 몬스터의 기본 방어 구역을 잠시 바꾼다.
- 적 집중은 선택한 적의 우선순위와 받는 피해를 실제로 바꾼다.
- 결과의 피해·회복·둔화·무력화·도난·돌파 수치는 실제 전투 사건에서 계산한다.
- 몬스터 한 마리의 슬롯을 바꾸면 생성 위치, 이동 경로, 첫 교전 구역 또는 최종 결과 중 하나 이상이 달라져야 한다.

## 6. DAY별 핵심 질문

| DAY | 플레이어가 해결할 질문 | 핵심 실패 |
|---:|---|---|
| 1 | 첫 전선을 Z1과 Z2 중 어디에 둘까? | 왕좌 피해 |
| 2 | 도둑을 추격할까, 미끼로 묶을까? | 보물 도난 |
| 3 | 공병을 먼저 끊을까, 시설을 분산할까? | 모든 시설 기능 상실 |
| 4 | 감시 초소와 임프로 후열을 노릴까, 적 집중을 쓸까? | 후열 압박 지속 |
| 5 | 용사를 후퇴선에서 받을까, 중간에서 막고 증원에 대비할까? | 왕좌 전실 돌파·증원 누수·도난 |

각 DAY는 자연 생성된 적이 이동·교전한 뒤 120초 안에 결과에 도달해야 한다. 화면 문구나 예상값만으로 승패를 만들지 않는다.

## 7. 변경 전후 확인

일상 작업은 아래 중 변경과 관련된 것만 확인한다.

- 상태 흐름을 바꿨다면 허용 전이와 재도전 1회
- 공간·배치를 바꿨다면 바뀐 슬롯에서 자연 전투 1회
- 전투·밸런스를 바꿨다면 해당 DAY 대표 대응 1회
- 저장을 바꿨다면 저장 왕복 1회
- UI를 바꿨다면 관련 테스트 1종과 `1280×720` 대표 화면 1회

전체 DAY, 모든 seed, 모든 플랫폼, 전체 회귀는 기본 요구가 아니다. 작은 확인에서 다른 영역의 회귀 증거가 나왔을 때만 영향 범위를 넓힌다.

## 8. 친구 테스트

일반 UI 확인은 3~5명에게 10~20분 정도 공유하고 아래 세 가지만 묻는다.

1. 어디서 막혔는가?
2. 어떤 글이나 정보가 필요 없거나 읽기 어려웠는가?
3. 배치를 바꿔 다시 해보고 싶은가?

표본 수와 점수로 기계적인 PASS를 만들지 않는다. 반복되는 막힘을 우선순위로 정해 수정한다.

## 9. 출시 경계

- `release/v2.0`을 그대로 `main`에 병합하거나 `v2.0.0` 태그로 만들지 않는다.
- 공개 출시 후보는 최신 `main`에서 별도 출시선을 만든다.
- 실제 공개 출시 전 검수 범위는 그 시점의 변경 내용과 배포 대상을 기준으로 사용자가 승인한다.
- 기존 `v1.2.1` 태그·Release·공개 빌드와 저장 데이터는 변경하지 않는다.
