# 최소 검수 정책

최종 갱신: 2026-07-26

이 문서는 앞으로의 기본 검수 기준이다. 목적은 오류를 놓치지 않으면서도 변경과 무관한 반복 검수로 개발 속도와 토큰을 낭비하지 않는 것이다.

## 1. 기본 원칙

1. 변경한 기능에 직접 연결된 가장 작은 테스트를 한 번 실행한다.
2. 실패하면 실패한 항목과 영향을 받는 항목만 수정하고 다시 실행한다.
3. 실행하지 않은 전체 검수는 실패가 아니다. 핸드오프에 `요청되지 않아 실행하지 않음`이라고 적는다.
4. 이미 통과한 대량 검수는 관련 코드가 바뀌지 않았다면 반복하지 않는다.
5. 검수 근거는 긴 보고서 대신 명령, 결과, 필요한 경우 대표 캡처 한 장으로 남긴다.

## 2. 변경 유형별 기본 검수

| 변경 유형 | 커밋 전 필요한 확인 |
|---|---|
| 문서만 변경 | `git diff --check`, 링크·경로 확인 |
| UI·문구 변경 | 관련 UI 테스트 1종, 영향받은 대표 화면 `1280×720` 1회 |
| 전투·밸런스·데이터 변경 | 관련 테스트 1종, 바뀐 DAY 또는 기능의 자연 실행 1회 |
| 저장 형식 변경 | 저장 왕복 또는 기존 저장 보존 테스트 1종 |
| 빌드·배포 변경 | 대상 플랫폼 부팅 1회, manifest 또는 배포 설정 확인 |
| 정책·CI 변경 | 해당 정책의 자체 테스트와 `git diff --check` |

한 변경이 여러 유형에 해당하면 중복되는 확인은 한 번만 실행한다.

## 3. 기본으로 생략하는 검수

다음 항목은 일상 구현·문서·커밋·푸시 전에 자동으로 실행하지 않는다.

- `tools/tests/RunCoreVerification.ps1 -Mode Quick`
- `tools/tests/RunCoreVerification.ps1 -Mode Full`
- 전체 회귀와 전체 플레이
- 모든 해상도·모든 플랫폼 반복 확인
- 별도 검수 에이전트 호출
- 70전·24전·10명처럼 고정된 대량 표본
- 통과한 테스트의 이유 없는 재실행

## 4. 큰 검수를 실행하는 경우

다음 중 하나일 때만 별도 범위로 실행한다.

- 사용자가 현재 작업에서 명시적으로 요청했다.
- 공개 출시 후보를 확정하는 작업이며 사용자가 범위와 시간을 승인했다.
- 작은 관련 테스트에서 다른 영역까지 퍼진 회귀 증거가 발견되었다.

이 경우에도 필요한 묶음만 선택하고, 예상 시간과 범위를 먼저 기록한다.

## 5. 친구 테스트

일반적인 UI·이해도 확인은 3~5명, 10~20분을 기본 제안으로 삼는다. 사람 수는 목표가 아니라 빠른 문제 발견을 위한 권장치다.

질문은 다음 세 가지면 충분하다.

1. 어디서 무엇을 해야 할지 막혔는가?
2. 필요 없거나 읽기 어려운 글·정보는 무엇이었는가?
3. 배치를 바꿔 다시 해보고 싶은가?

친구 테스트 결과는 개선 참고 자료다. 공개 출시 확정용 판정이 필요할 때만 별도 기준을 합의한다.
