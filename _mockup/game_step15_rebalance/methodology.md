# B04 측정 방법 — 0119 복구 후 최종 범위

고정 시드 130401~130410을 새 게임부터 실제 합류·성장·특화·승급·원정·정상 비용 건설·추천 배치·정산·엔딩까지 진행한다. 날짜·성장·HP·자원·강화는 직접 주입하지 않는다. 첫 3일 x1, 정상 해금 뒤 x3, 실제 60Hz 계산과 기본 수비 지침을 유지한다. 별도 건설 추천 서비스가 없어 승인 도면의 빈 부지를 결계핵·병영·회복 둥지·감시탑·미끼 금고 순으로 구매한다. 배치 인원 또는 선호가 개선되는 강화만 구매하고 필수 승급용 마나 60을 남긴다. 실제 구매 API의 해금·정원·가격·잔액 검사를 따른다. 필수 선택은 첫 합법 선택지, DAY29 선언은 castle_oath다.

최종은 정상 재도전 1회 포함 엔딩 ≥7/10을 판정한다. 같은 날 두 번 지면 종료한다. 재도전의 회복·비용은 실제 제품 버튼만 사용한다. 날짜 곡선은 실제 도달 회차의 **첫 전투** 승률과 패배 HP 0의 평균이며, 재도전으로 첫 패배를 덮지 않는다. 시작 10회 누적 지표도 병기하고 미도달 전투값은 CSV에서 빈칸으로 남긴다. DAY29는 준비·무전투다. 초기 v8과 후보 v9의 재도전 0은 별도 강화 진단이다. 라운드당 10시드 1회는 캠페인 실행 횟수이며 정상 재도전 금지가 아니다. 재도전 없이 9일 모두 승률 95% 이하와 완주 7/10은 양립하지 않는다.

시작 11:47:35 UTC, 후보 탐색 종료 14:40:26 UTC(2026-10-18)로 최초 3시간 한도 14:47:35 UTC 안이다. 후보는 정확히 2라운드다. v9는 새 게임 10시드→DAY30/재도전 0, v10은 바뀐 DAY15와 다음날의 결과만 보기 위해 새 게임 10시드→DAY16/재도전 1로 제한했다. v10 후반을 추정하지 않는다. 두 후보는 중반 승률 100%를 낮추지 못했고 HP 목표 편차가 늘어 폐기했다. v8 웨이브를 유지한 뒤 대표 배치 경유만 조정했다. DAY15~23 최신 목표는 승률 80~95%·HP 45~75%다. 최종 v13_final은 새 게임 10시드→DAY30/정상 재도전 1회로 한 번만 실행한다.

대표 날짜는 DAY1·5·10·15·20·24·27·30이다. DAY10은 실제 제품에서 F등급이며 E로 주입하지 않는다. v9에서 실제 생성한 진입본 80개를 고정해 현재 채택 웨이브로 추천/병영·결계핵·옥좌 집중/최종선 집중/1차선 집중을 비교한다. 최종 캠페인의 성장 경로와 같다고 주장하지 않는다. 각 네 배치의 성장·특화·HP·자원·시설·강화·선택과 원본 SHA-256을 대조한다. seed+DAY×1000의 공통 실험 RNG를 쓴다. 실제 보유·방어 자격·정원·고유 칸·식량을 검증하고 배치 수 차이도 표시한다.

처음 320전투 뒤 실패한 DAY5·10·15·27·30만 경유를 각 1회 바꿔 200전투로 재확인했다. DAY10·27·30을 채택했다. DAY5는 추천 우위가 생겨도 HP 89.07%로 초반 목표를 벗어나 원복했고 DAY15는 집중 대비 HP 격차가 더 커져 원복했다. 남은 DAY5·15·27 열세를 숨기지 않는다. 추가 경유 탐색·재확인은 없다. 보고기는 날짜별 실제 선택 웨이브와 일치하는 최초/재확인 자료만 채택한다.

HP는 전투 종료 기준이다. 실제 종료와 정산은 지연 호출 경계로 나뉘므로 정확히 300단계 배수에서 끝난 일부 기록은 정산의 성 진화 +250/+350/+400 HP가 먼저 반영될 수 있었다. 원본을 수정하지 않고, 진입 최대 HP·실제 다음 단계 정의·승리·실제 진화 이벤트·동일 정산 HP를 모두 검증한 경우만 그 보너스를 분리한다. 원본 HP/최대 HP/보너스는 CSV와 evidence_manifest에 함께 남긴다. 그 외 최대 HP 변화는 오류로 거부한다. 프레임 경계 양쪽의 동일 결과·실제 전투 피해/패배 보존·근거 없는 변화 거부를 Python 회귀 검사로 확인한다. 이 보정 후에도 후보 채택/폐기 판단은 같다. v10 HP 편차합은 원본 7.91%p에서 보정 후 7.53%p다.

모든 실행은 별도 APPDATA/LOCALAPPDATA와 Steam 비활성 환경이다. 격리 경로 검사가 실패하면 게임 생성 전에 종료한다. Godot는 작업당 1개, 종료 시 0개를 기록한다. 기존 저장 비활성 시험 규칙을 유지하므로 G01 정식 저장/이어하기 근거가 아니다. 화면 처리만 생략하는 하위 클래스를 쓰고 정적 지도 캐시는 setup에서 초기화하며 가변 함정 종류를 분리한다. 전투 계산은 바꾸지 않는다. 이어받은 난수 상태 재현 도구는 혼합 호출 75검사로 확인했다. 실제 렌더·EXE Computer Use·전체 회귀·출시 검수는 이번에 실행하지 않는다.
